# AllDayRecording-ASR 项目现状与路线图

> 盘点日期：2026-08-28  
> 当前阶段：V1 离线原型已跑通，进入质量评测与流程固化阶段。

## 1. 结论

项目已经越过“技术路线设计”，具备一条可实际运行的离线处理链路。它可以把一段 Watch 长录音变成可追溯的转写和事件时间线，也已经建立了“独立本人声纹 → 候选片段 → 人工真值 → 留出/负样本库”的闭环。

当前最主要的问题不是缺少更多模型，而是缺少一套可重复的真实场景评测、稳定的一键日处理流程，以及针对短句、电视和多人混合场景的说话人切分改进。实时化应排在这些基础工作之后。

## 3. 当前真实测试结果

测试对象为一段华为 Watch 录音：2 小时 44 分 35 秒，16 kHz 单声道 AAC/M4A。

| 指标 | 结果 |
| --- | ---: |
| VAD 语音片段 | 423 |
| 检出语音总时长 | 737.53 秒 |
| 完成转写片段 | 423 / 423 |
| SenseVoiceSmall 纯 ASR 时间 | 24.92 秒 |
| 纯 ASR RTF | 0.0338 |
| ASR 峰值显存 | 约 979 MiB |
| 质量审计后保留匿名标签 | 115 片段 |
| 质量审计后 `unknown` | 308 片段 |
| 人工确认本人片段 | 5 |
| 人工身份/负样本标注 | 17 |
| 规则聚合事件 | 10 |

质量审计后匿名标签分布为：`speaker_00=31`、`speaker_02=8`、`speaker_03=39`、`speaker_04=37`，其余 308 段为 `unknown`。

这组数据证明长录音处理速度和可续跑链路可行，但不能证明说话人识别已经准确。人工试听已确认：原匿名聚类会混入本人、父母和电视，不能整簇绑定真实身份。

## 4. 当前声纹库

本人档案当前包含 23 个活动 embedding、约 173.33 秒有效登记语音，状态为 `active`。样本库有：

- `accepted`：9 条独立登记来源记录。
- `holdout`：5 条来自本次录音的人工确认本人片段。
- `negative`：12 条，包括母亲、电视、混合和不确定样本。
- 当前实验阈值：`0.36`。

这些数据足以验证完整闭环，不足以证明阈值已经泛化。阈值必须在更多日期、地点、设备距离和噪声条件下评测，不能把当前数字当成固定产品参数。

## 5. 已知技术债和风险

1. 只有一段长录音和 17 条身份标注，尚未建立 15～30 分钟的完整人工真值集，也没有 CER、说话人错误率、误接受率和误拒绝率。
2. 当前 diarization 先按模型说话人区间映射到 VAD 片段；一个 VAD 片段内的换人、重叠讲话和电视声仍可能混在一起。
3. 所有阶段需要手工逐条执行，缺少幂等的 `daily-run` 一键编排和真实文件集成测试。
4. 时间线只是时间间隔规则聚合，还没有“我今天做了什么”的摘要，也没有时间、地点、承诺和待办候选。
5. 固定人物可以登记，但尚无通用的跨天人物候选匹配和人工确认流程。
6. SQLite 只有 `CREATE TABLE IF NOT EXISTS`，尚无 schema 版本和迁移机制；继续扩表前应先补齐。
7. 模型参数和阈值仍分散在命令默认值中，缺少录音级配置快照和统一配置文件。
8. 项目尚无 Git 基线提交；当前源码和文档均处于未跟踪状态。

## 7. 推荐下一步

### P0：先把离线原型变成可评测、可重复的 MVP

1. **补 schema 版本、迁移和统一配置。** 先稳定数据协议，避免后续功能扩展破坏已有声纹库和标注。
2. **建立真实人工评测集。** 从现有录音选 15～30 分钟，标注语音边界、文字、说话人类别、本人/电视/混合、时间地点等关键事实；增加 CER、关键事实准确率、误接受/误拒绝统计命令。
3. **改进说话人切分。** 优先解决一个 VAD 片段内换人、短句和电视声，不急着更换整个 ASR 模型。聚类只能作为候选，身份仍按片段或更小窗口确认。
4. **增加 `daily-run` 编排。** 一条幂等命令完成 ingest → process → diarize → 身份候选 → timeline → export，并清楚报告“自动完成”和“等待人工确认”的阶段。
5. **增加真实文件的轻量集成测试。** 使用不含隐私的小样本，验证断点续跑、重复运行和导出结构。

### P1：验证产品核心价值

在离线文本上先实现日程/待办候选，而不是立刻做实时传输：

```text
转写片段
  → 时间、地点、人物、动作和确认语提取
  → 合并“对方提出 + 我确认”的上下文
  → 生成带原音证据的候选
  → 用户确认/修改/忽略
  → 之后才接日历写入
```

第一批只处理高价值、可核验的结构：明确日期时间、地点、参与人、待办动作。系统必须保留原文和音频证据；没有用户确认时不写入日历。

同时增加通用的“固定人物候选 → 人工确认 → 跨天积累”流程。陌生人仍默认匿名，只有用户主动选择且对方知情同意时才建立长期档案。

### P2：最后实时化

1. 增量 VAD 和流式 ASR，区分临时文本与稳定文本。
2. 手机/Watch 到电脑的分块传输、断线续传和时间同步。
3. 后台事件候选检测与桌面确认弹窗。
4. 用户确认后的系统日历/待办连接。

实时阶段仍应保留离线重处理：实时结果追求低延迟，离线结果负责最终准确度。

## 8. 下一轮最合理的交付目标

下一轮建议定义为：**“可评测的一键离线日记 V1”**。

完成条件：

- 有 schema 迁移和统一配置快照。
- 有一段可重复使用的人工真值集和自动评测报告。
- `daily-run` 能安全重复执行，不覆盖原音或人工标注。
- 输出当天转写、事件时间线、本人候选和待确认项的统一清单。
- 在此基础上增加第一版离线日程/待办候选，不接真实日历。
