# AllDayRecording-ASR 项目现状与路线图

> 盘点日期：2026-08-28  
> 当前阶段：可评测的一键离线日记 V1、本地操作台和首份人工基线已建立，下一步据此改进切分并扩充跨场景真值。

## 1. 结论

项目已经越过“技术路线设计”，具备一条可实际运行的离线处理链路。它可以把一段 Watch 长录音变成可追溯的转写和事件时间线，也已经建立了“独立本人声纹 → 候选片段 → 人工真值 → 留出/负样本库”的闭环。

当前最主要的问题不是缺少更多模型，而是缺少一套可重复的真实场景评测、稳定的一键日处理流程，以及针对短句、电视和多人混合场景的说话人切分改进。实时化应排在这些基础工作之后。

## 4. 当前声纹库

本人档案当前包含 23 个活动 embedding、约 173.33 秒有效登记语音，状态为 `active`。样本库有：

- `accepted`：9 条独立登记来源记录。
- `holdout`：5 条来自本次录音的人工确认本人片段。
- `negative`：12 条，包括母亲、电视、混合和不确定样本。
- 当前实验阈值：`0.36`。

这些数据足以验证完整闭环，不足以证明阈值已经泛化。阈值必须在更多日期、地点、设备距离和噪声条件下评测，不能把当前数字当成固定产品参数。

## 5. 已知技术债和风险

1. 已建立首个连续 15 分钟真值和报告，但只有 46 段能可靠听写、本人正样本仅 2 段；仍缺少跨日期、跨距离和更多本人发言的评测集。
2. 当前 diarization 先按模型说话人区间映射到 VAD 片段；一个 VAD 片段内的换人、重叠讲话和电视声仍可能混在一起。
3. `daily-run` 已能安全编排现有阶段，但还缺少一份可公开提交、不含隐私的小音频集成样本。
4. 时间线仍然只是时间间隔规则聚合，还没有“我今天做了什么”的日级摘要；行动候选目前只覆盖明确日期、时间和本人承诺的严格格式。
5. 固定人物可以登记，但尚无通用的跨天人物候选匹配和人工确认流程。
6. schema v3 迁移已经建立；后续每次结构变化都必须新增迁移版本，不能修改既有迁移。
7. `daily-run` 已使用统一配置；旧的分步命令仍保留各自参数，后续可逐步接入同一配置层。
8. 已建立 Git 基线提交 `d9e9377` 和一键日记提交 `57cbe2e`；后续能力继续按可验证功能独立提交。

## 7. 推荐下一步

### P0：先把离线原型变成可评测、可重复的 MVP

1. **整理并冻结首份基线。** 将纯吃饭声等非语音排除；电视应作为声音来源类别，不应把节目中的所有人物当成同一个说话人。冻结后保存真值 SHA-256。
2. **改进语音切分。** 优先解决电视声和短句被切得过碎的问题，再用相同真值比较 CER 和可听写覆盖率；不急着更换整个 ASR 模型。
3. **扩充真实人工评测集。** 增加更多本人发言、跨日期、跨距离、安静与嘈杂场景，才能计算可信的本人误接受率和漏接受率。
4. **增加真实文件的轻量集成测试。** 使用不含隐私的小样本，验证断点续跑、重复运行和导出结构。

### P1：验证产品核心价值

离线日程/待办候选的规则 V1 已实现，下一步用人工真值提高覆盖率，而不是立刻做实时传输：

```text
转写片段
  → 时间、地点、人物、动作和确认语提取
  → 合并“对方提出 + 我确认”的上下文
  → 生成带原音证据的候选
  → 用户确认/修改/忽略
  → 之后才接日历写入
```

第一批只处理高价值、可核验的结构：明确日期时间、地点、参与人、待办动作。系统已保留原文和音频证据；没有用户确认时不写入日历。后续需要加入更丰富的自然语言日期解析和基于上下文的候选召回。

同时增加通用的“固定人物候选 → 人工确认 → 跨天积累”流程。陌生人仍默认匿名，只有用户主动选择且对方知情同意时才建立长期档案。

### P2：最后实时化

1. 增量 VAD 和流式 ASR，区分临时文本与稳定文本。
2. 手机/Watch 到电脑的分块传输、断线续传和时间同步。
3. 后台事件候选检测与桌面确认弹窗。
4. 用户确认后的系统日历/待办连接。

实时阶段仍应保留离线重处理：实时结果追求低延迟，离线结果负责最终准确度。
