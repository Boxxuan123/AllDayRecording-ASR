## 测量口径

在同一台真实手机上，使用正式 DeviceRemote、HUKS 认证、UseCases、原生 SQLite Repository、ViewModel、同步协调器和正式标注页面。数据量为 6,969 条合成发言。每组 20 次单条、5 次 32 条，32 条保留 32 个独立 operation ID。单条 P95 采用 nearest rank（20 个样本中的第 19 个）。批量目标按最慢一次判定，不拿平均值替代。

起点是调用正式保存标注前，包含本地入队；终点是所有目标记录已确认且界面触发 didLayout。这个终点比 ViewModel 的 T6 日志更靠近显示，不是显示面板的光学测量。页面导航在保存前启动；真实页面布局的延迟被保留。

并发组：16 MiB 合成录音经过正式签名分片上传链路；接收器对每块增加 200 ms 延迟，以保证采样期间上传持续。真实样本工作器处理同一批合成事实，执行实际 FFmpeg 截取和本地 CAM++ 推理。压力生成器反复将会话标为待处理，以维持持续后台负载，比日常只处理变化更重。采样期间手机上传进度从 131,072 增至 4,521,984 字节；电脑记录 10 次真实模型调用。标注回执全部 applied，没有冲突或丢失。

16 MiB 上传在标注采样结束后为切换对照测试而停止；它证明分片上传与标注并发，不代表该合成录音最终 manifest 完成。

## 分段耗时

下表为各阶段的 P95，单位 ms。各阶段的 P95 来自不同样本，不能相加为端到端 P95。

| 阶段 | 空闲单条 | 空闲32条 | 并发单条 | 并发32条 |
|---|---:|---:|---:|---:|
| 认证（含挑战往返与手机签名） | 146.0 | 683.2 | 7299.1 | 2798.6 |
| 建立写事务的等待 | 2.4 | 13.7 | 15.3 | 70.9 |
| 业务处理 | 46.7 | 792.8 | 49.0 | 1934.8 |
| 业务请求传输／原生栈残差 | 25.6 | 104.0 | 146.8 | 7922.4 |
| 手机回调排队 | 26.1 | 59.7 | 18.1 | 75.5 |
| 手机落库 | 21 | 281 | 24 | 331 |
| 界面状态刷新 | 29 | 217 | 57 | 290 |

定义和限制：

- 写事务等待：同步服务进入至获得写事务，含少量连接／仓储初始化；事务持有时间另外记录在逐样本 JSON 中。
- 业务处理：服务器同步服务总耗时减写事务等待，包含读取投影和生成响应。
- 认证包含 challenge 的网络往返。因此“认证慢”不能直接解释为签名算法慢。已有记录能区分手机请求总耗时、原生 HTTP 耗时及电脑处理耗时。
- 传输／原生栈残差：手机原生 HTTP 总耗时减同请求电脑 handler 耗时，含网络、内核、原生栈及观测边界外排队，**不是抓包测得的纯链路时间**。这里仅统计业务／连接状态请求，challenge 往返留在认证列。
- 手机落库：T4（解码完成）→T5（回执原子提交），含紧邻提交的结果整理。界面刷新为各批 T5→T6 的累计；逐样本另记 T6 到布局终点差值，实际验收始终用完整起终点。
- 所有间隔分别来自各端本地时钟，不直接相减电脑和手机的绝对时间。原始请求 ID、operation ID 与事件时间均保留。

## 长尾定位与 USB 对照

例如一条局域网业务请求：电脑在约 657 ms 内处理并写出响应；手机原生网络栈报告约 4,497 ms，额外约 3.84 秒。另一条电脑约 365 ms，手机约 8,404 ms。并发时，一个认证挑战在电脑约 280 ms 完成，手机等待约 7,096 ms。

USB 转发保持同一接收服务、TLS 校验、数据库和模型，替换局域网路径。并发组单条 n=20，P95 **1,547 ms**；32 条 n=5，最大 **4,648 ms**。这组达到目标，不能替代局域网验收。

USB 前半组仍有上轮持续样本工作器运行，不能称为空闲基线：单条 P95 1,443 ms，32 条最大 5,644 ms；一项样本的 T6 到布局相隔约 1.735 秒，需要继续区分界面绘制与状态更新。

证据支持“局域网／原生传输路径长尾是主要问题之一”，尚不足以确定是无线链路、电脑／手机驱动、系统代理或其它网络处理环节。当前进程没有系统抓包所需权限，PktMon 驱动拒绝访问，未取得 TCP 包级证据；未绕过权限，也未改动系统代理或网卡配置。

## 后续处理优先级

1. 对局域网慢请求采集两端 TCP 时间线，定位电脑写出至手机首字节之间的停顿；同时用干净网络路径对照。保留请求 ID 和服务器耗时，避免把网络等待归到 SQLite。
2. 对稳定连接跨同步轮次复用已验证的协议状态，减少每次标注重复状态挑战；保留配置变化失效及每个业务请求的签名和重放保护。
3. 根据端到端延迟一起调整批量策略。当前 150 ms 写事务目标会将批量缩至约 4–6 条，32 条需要多轮认证；需要平衡锁占用与往返次数。
4. 针对真实标注页面补帧级跟踪，区分 T6 状态更新和最终布局／绘制，不能仅凭 T6 判定手机可见确认。
