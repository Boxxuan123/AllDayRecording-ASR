# 跨天记忆连续性与有限增量（ASR 0.7.3 / Phone 1.0.11）

本轮基线 ASR 709143f9502ff8d4ab32f8ff89638abc34bdb91a、Phone c5d34d17e488e89e1698bbcdf7aaf94ded6f554a。复用隔离工作树；原工作区修改保留。

讨论依据明确的讨论对象、原消息回复边和具体操作衔接分段；无可识别对象的实质陈述保留独立不确定记录。处理批次和八条引用页不决定讨论边界。旧讨论通过原消息引用恢复稳定 ID，不破坏底层事件或人工关联；已有多段记录之间的具体连续性仍形成审核建议。核心依据与图片、访问材料及链接上下文分别标识。每条引用明确显示发送者、is_from_self、身份依据、时间及原修订，身份来自源记录，不推测措辞。

七段是每次主动更新的新内容处理预算，七段同时是每页展示量，均不是总存储容量。沿用 cross_day_index_revisions 的不可变 scope_json 持久保存已处理 manifest、等待 _pending、排除 _excluded、输入修订签名和批次 ID。新工作与旧积压交替取入有限批次；来源更改导致发布失败时整笔进度回滚。相同输入不自动消费积压，电脑“继续下一有限批次”显式提供 batch_id；网络重复请求和重启不消费两次。同一窗口可以恢复既有积压及已处理历史。只在所选最多三天、三联系人、5000 条缓存边界中处理，无后台监听或全历史提取。

日期只限定处理与当前默认页。沿用既有不可变修订找回其他窗口的已保存讨论，并在已有 memory_index 资源类型中提供独立历史页和引用页。主索引 ID 保持不变，每页最多七段、每段每页八条引用；不传原始附件、全量聊天或音频。手机按主索引修订筛选缓存页，旧页和旧修订重放不能覆盖新修订。现有待确认入口读取有效的全窗口候选，旧候选也可以通过历史页找到；确认、拒绝、撤销沿用 memory.link outbox、回执和冲突机制。操作前校验涉及的历史引用；失效证据退出待确认而在历史中明确显示失效。

GET/同步仅复核冻结引用和所选身份，不再重复调用日期盘点和每日来源检查；历史页及待确认候选只做有限引用复核。显式更新仍有三天/5000 条盘点边界。正常全历史刷新性能与 Calendar 实体提醒保持独立未测项。

兼容契约补丁 3.10.1，投影版本 7，Core 对外 34（私有 35），Phone 21。新增可选 page、processed_discussions、证据身份及角色字段，新增可选 GET 分页参数和更新续批参数；命令、稳定 ID 与数据库表不变，无迁移。旧客户端仍读取不超过七段的主索引。分发通过 canonical contract manifest/receipt 校验。

合成回归固定覆盖 7 已处理 + 24 等待 + 1 新互动、公平续批、排除、失败回滚、重启及幂等；跨窗口候选通过真实 Phone SQLite/outbox/Python 对端确认、拒绝、撤销、回执和旧修订重放。真实试点及设备审核仅存本地忽略目录，模型调用为零；真实跨天变化不足时不宣称已验证跨天事实。
