## 实现位置与规则

- `src/allday_asr/v3/domain/chat_identity.py`：`checked_identity`、`message_self`、`actor_identity` 保持 true / false / null；true 直接本人、false 直接非本人，null / 缺字段保留未知及已有人工确认。自动映射不将未知消息变成已确认。不比较采集 ID 与发送者 ID，不按昵称判断。`frozen_record`、`merge_live_identity` 将读取时身份元数据与冻结原修订分开，包含嵌套引用记录。
- `src/allday_asr/v3/adapters/sqlite/chat_cache.py`、`chat_identity_cache.py`：在已有私人缓存内增补观察、人工纠错审计和刷新回执表，保持缓存 schema 1；自动映射以 platform / source_account_id / sender_account_id 为键，保留多个有 true 证据的发送者，展示依据与冲突；人工映射表及纠错来源保留。true 且发送者空时仍为本人，不造 ID。缓存查询、原文上下文、已有回答证据贯通两个字段。旧回答的证据身份改变后标记 `self_identity_stale`，不擅自改写旧推理文本。
- `src/allday_asr/v3/application/chat_identity_refresh.py`：`IdentityRefresh` 固定已有记录 ID 和修订的工作集，POST /v1/records 每批至多 100 条，逐项检查 status / ID / 修订 / 冻结正文。不修改原文、稳定 ID、修订或增量游标。最多 5,000 条、200 次请求、300 秒累计预算；每项最多三次尝试，仅有限重试可恢复故障，支持取消、暂停和续接。请求计数与时间预算在请求前持久化，崩溃不会清零；中断后按已保存 ID 重试具有幂等性。缺失、修订不可用、正文变化及畸形返回分别记录失败。
- `src/allday_asr/v3/application/chat_followup_identity.py`：`rebuild_identity` 只重判已有候选和缓存证据；既有准入、去重、事件来源及人工保护链路保持生效。`hydrate_identity` 读取旧卡片时更新说话主体元数据，不覆盖人工标题、分类和状态。原审核绑定不把读取时身份字段纳入正文摘要。
- `src/allday_asr/v3/bootstrap/chat_followups.py`、`domain/chat_followups.py`、`domain/chat_admission.py`、`adapters/chat_data/followup_model.py`、`domain/chat_projection.py`：接入 scoped 本人映射与每条消息的方向标记；模型输入仅携带必要身份字段，未调用模型。解释键不包含观察时间和证据计数，重复刷新不会制造新事项操作。
- `all_day_recording_front/v3/core/chat.ts`、`views/ChatView.vue`、`views/FollowupsView.vue`：本人 / 非本人 / 未知标签、自动与人工映射数、冲突提示、刷新进度及原人工入口；旧回答失效状态沿用已有呈现规则。
- `tools/refresh_chat_self_identity.py`：可重复运行的有限回填入口，进度输出不包含实际账号、会话或正文。

