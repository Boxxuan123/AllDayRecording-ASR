## 核实的审核问题

读取用户提供的独立报告和 ZIP 中两个探针，将探针指向实际基线提交的模块执行。原始行为复现成功：空 grants 回退请求没有 conversation_id，接收了其他会话；31 条证据的模型输入不含最初 e00。探针只使用虚构对象，不连接网络、数据库或真实模型。没有运行包内 pyc。

这个范围问题是回退分支的函数级证据：当前正式 `RecallState.authorized_scopes` 对 source_contacts 会直接返回会话 grants，不能据此宣称生产已发生泄漏。修复仍覆盖回退、已有账号 grant 和已有会话 grant，同时补上原有回包校验缺失的私聊对方及会话类型约束。

## P1：请求与回包持续执行来源限制

新增纯函数 `domain/recall_investigation_scope.py`，用于将已有 grants 或目录回退候选与平台、采集账号、会话、显式发送者取交集。约束互相矛盾时不发出请求，不回退到更大范围；已确认人物没有 grant 时也不回退到全账号。

`search_remote` 始终发送交集中的 conversation_id。返回页逐条验证平台、采集账号、会话、日期、显式发送者；额外检查选中联系人的会话类型与对方账号。私聊保留原生方向确认的本人消息及指定对方消息；错误对方、未知方向或伪装群聊被拒绝。群会话允许本群已观察到的发言，不由此推断成员资格或角色。

违规页在加入证据前整体拒绝；已读取条数仍计入预算。超过两个远端范围的分支明确报告未覆盖。未增加请求、记录或模型限额。

## P1/P2：固定上限内选择证据并披露遗漏

新增纯函数 `domain/recall_evidence_selection.py`，替换无条件最新 20 条截取：

1. 优先保留已执行计划的支持引用、证据目标及已有结论引用。
2. 保留种子/各检索步骤的最早与最新记录，以及不同来源、会话、发送账号、证据类型的时序边界。来源元数据与转述分别保留。
3. 剩余容量按各来源的时间区间分层取样，补充中间记录，而不是只看最新消息。最终按时间排序交给模型。
4. 原来的 **20 条 / 28,000 UTF-8 字节**保持不变，字节检查包含完整 JSON 数组；先完成原有内容清洗。超大记录不会挤掉全部其他证据。
5. 模型收到所选/遗漏数、必要锚点遗漏数及 ID。只要有已取得证据没被送入模型，应用层强制 `partial`、补充未知项和部分依据说明，步骤不得标为证据充分。手机现有覆盖提示和未知项直接呈现这些限制，无需改 UI 或契约。

这不是语义变更检测器：不增加“取消/改期”等故事词规则，也不声称时序抽样能保证发现每条关键变更。锚点、各来源端点能被优先保留；未被引用的中间状态仍可能遗漏，必须标为部分覆盖。完整语义蕴含和真实召回仍待单独预算授权后的真实模型盲测。
