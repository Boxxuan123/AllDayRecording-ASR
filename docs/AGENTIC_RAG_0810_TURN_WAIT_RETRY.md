# Agentic RAG 0.8.10：turn_wait 分层记录与有界重试

本轮按用户追加授权重放已有三份虚构案例的第二轮输入；没有新增盲测，没有重新运行检索规划轮，没有部署。旧留出集现在已用于诊断和调试，不再称为盲测。25 秒单次截止、low 推理强度、所选 gpt-6-astra、每题两轮和既有检索边界不变。所有失败保留，不接受部分 JSON，不无限自动重试。

## 发现与修复

1. `turn_wait` 包含整个服务端响应流，而非单纯等待最终完成通知。新增流事件计数、首末时间、输出字节数、JSON 是否完整、item 类型、usage 和服务端 duration。仍由固定 SDK 0.160.0 的原 collector 判定 turn/completed；完整消息但没有完成事件仍失败。诊断文件不保存增量正文或思维链。成功时记录的服务端 duration 包含的服务内部阶段无法进一步拆分；收到 delta 的时间也不能单独区分生成速度与网络传输速度。
2. 历史调查任务使用简短 base instructions，关闭该子进程的 apps/plugins/shell 和 host skill discovery；不修改全局配置，不影响其他任务。仍不宣称隔绝所有 SDK 注入内容。相同烧制输入的已完成回执在早期版本报告 17,842 输入 tokens，后期为 13,664；这是多项修改后的观测差异，非严格单变量因果实验。
3. 最终轮只让模型输出 claims/candidates/unknown，程序补齐固定信封。至多两条 120 字结论、64 字时间引文、三条 120 字不足说明，保留引用和原有真假/时间校验。最终轮不再要求输出无法再获模型总结的新搜索计划；证据不足明确报告 unknown。该长度限制可能不足以完整回答复杂问题，本轮三例不能证明普适覆盖率。
4. 向证据附加由 sent_at 与用户 IANA 时区确定的 sent_at_local，原记录不变；它是消息时间，不能代替事件时间。
5. 第 8 次模型已完成，但本地把“前天……昨天也……”按用户查询日期歧义拒绝。新增专用来源日期校验：只组合明确、相邻的自然日；拒绝缺日、绝对/相对混合、替代选项和不支持的时间描述。来源原文、引用归属、日期一致性仍严格验证。用户查询解析器保持原限制。保存的第 8 次回答离线重放通过，随后第 9 次真实重试也通过。
6. 第 11 次线程启动约 4.8 秒。只读关联运行日志显示 SDK 0.160.0 与共享目录缓存 0.162.0 版本不匹配，随后 `/models` 请求耗约 4.7 秒。为调查任务复制一小时内、含所选模型的目录为内容寻址快照，保留目录元数据，不伪造版本、不改共享缓存。自定义 provider、profile 或 catalog 配置不覆盖；缺失/过期目录继续走 SDK 原路径。快照哈希和配置进入请求身份。预检没有模型调用，thread ready 0.265 秒，总 1.312 秒。

本地 SDK 缺乏该配置的完整说明时核对了 [OpenAI 配置参考](https://developers.openai.com/codex/config-reference/) 中的 model_catalog_json 启动配置，并通过已安装 0.160.0 实际预检验证。目录内容保留在私有回执，不收入公开审核包。

## 证据与限制

三例均复用 0.8.9 已由真实模型检索得到的四段证据链：起始群 A → 共同群 A/B → 后续私聊 B，且同名干扰账号未混入。已有请求、检索步骤与四段原文供审核者核对。最终简短回答不一定逐项引用全部桥接消息，因此“最终引用包含全部桥接链”不能算通过；本轮只能验证已获得完整证据后的最终回答，不能替代新版本端到端陌生案例评估。

烧制回答区分原计划、后续称未开窑、附条件的新计划；题稿回答区分指控、demo/提交澄清与未完成全面合规审核；采声回答区分 13/14 日未成行与 17 日待许可计划。所有结论都保留为 statement/不确定性，未把聊天说法升级为事实。

目录预检不等于模型成功；最终调用结果、工程测试、完整失败表及累计资源见下方本轮最终记录。无 Windows/Phone 部署，无私人数据库修改，Phone NO CHANGE。

## 最终记录

最终同一实现的三个旧输入均完成并通过程序校验：第 16 次题稿 23.844 秒，第 17 次烧制 24.891 秒，第 18 次采声 21.094 秒。人工核对三例均未混入同名干扰，保留更正、条件与未知；只有题稿最终引用显式包含四段桥接原文，另外两例未完整展示桥接引用，不能宣称完整 ACM 验收通过。烧制接近 25 秒截止，稳定性仍未建立。

- 累计 18 次执行尝试，实际提交 **17 次模型调用**：8 次得到完整模型结果，其中第 8 次被本地日期校验拒绝；7 次完整答案通过；9 次超时。第 15 次是 SDK 启动配置错误，无模型 turn。另有一次无 turn 的目录预检。
- 尝试累计墙钟 **410.579 秒**（不包括开发、测试和目录预检）。已报告用量 **117,013 tokens**；9 次超时 usage 未知，不能记零或称为精确总消耗。最新三例使用原 gpt-6-astra / low，没有替换更快模型或增加预算。
- 完整离线回归 **1384 passed、1 skipped、27 warnings，583.58 秒**，在最后目录/MCP 修复前启动。最后两项修复后另跑相关执行器、诊断、追踪、结构回归 **33 passed，4.21 秒**。没有把前一次全量冒称为最终实现重新跑过的全量。Ruff 和 git diff --check 通过。无新增 skip，修改生产模块不超过 389 行。
- 第 12–14 次证明仅修目录不够：三次仍超时。第 12 次虽然 1.141 秒已进入 turn_wait，但 23.406 秒（诊断观察器起点）才收到首段回答，不能把剩余耗时全部归于输出长度。子进程还继承全局 node_repl。随后对调查任务追加禁用全局配置中名称可由 SDK dotted-key 覆盖的 MCP；不修改全局文件，不复制服务器命令、环境或密钥。含点等特殊名称不覆盖，因此不宣称全面无工具隔离。第 15 次错误证明 SDK 覆盖键不能直接使用 TOML 引号路径；修为可表示的普通键并补回归，第 16–18 次完成。
- 全部尝试、事件计数、用量、完整成功回答与失败回执保留在审核包。第 11/12 次的运行日志只保留限定子进程的白名单事件元数据，不保存原始 HTTP 日志、Cookie、配置正文或思维链。

以上成功是反复调试后的旧输入回放，不是新的盲测通过率，也不是新版检索端到端一次成功率。仍有服务端/传输等待波动、最终引用链展示不足与真实历史覆盖未知；本轮停止新增调用，交付独立审核，暂不部署。
