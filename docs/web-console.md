# 本地网页工作台

网页工作台用于操作现有的离线录音、人工真值、语义证据和行动候选。它不负责实时录音，也不向外部服务上传数据。

## 启动

在项目虚拟环境中执行：

```powershell
allday-asr web
```

默认监听 `127.0.0.1:8765` 并打开浏览器。如果端口被占用，可以改用：

```powershell
allday-asr web --port 8766
```

不希望自动打开系统浏览器时使用 `--no-open`。终端会打印带一次性随机令牌的完整地址；应从该地址首次进入，浏览器随后用仅本机 Cookie 保持会话。停止服务请在终端按 `Ctrl+C`。

## 推荐操作顺序

1. 在顶部选择录音。若已有完成的 V2-D run，“说话人时间轴”会默认打开。
2. 先听“多人对话”队列。它用 90 秒窗口、30 秒步长，按有效语音、ASR 文字、匿名说话人数、切换次数和真正重叠综合排序。
3. 再按需检查“重叠说话”“无归属文字”和“可能漏检”。“可能漏检”的琥珀色范围是低置信召回补救，只用于人工试听，不会写成正式说话人结论。
4. 时间轴中的词可以点击并跳到对应音频时间；确定/可能语音、人工来源真值、人工身份真值和匿名说话人相互独立。人工身份只覆盖已标短区间，token 上的“母亲/父亲/电视”角标是审计真值，不会把整个匿名簇改名。污染矩阵会显示同一匿名 speaker 混入了哪些人物；斜纹表示同时说话，红色虚线表示没有可靠说话人归属。
5. 需要建立人工真值时，切换到“评测标注”，选择评测模板并填写准确文字。
6. 能判断时再填写真实说话人和“是否本人”；不能判断就保留为空。电视、混合讲话或远场噪声写入备注。
7. 保存后，点击“生成评测报告”建立当前模型基线；行动候选只确认有充分原文证据的条目。
8. “语义证据”页可以从最新匹配的 V2-C/V2-D run 生成 V2-E.0.1 本地证据包。每张卡代表一个无固定时长上限的完整对话，可切换最多 120 秒的本地回听片并追加人工确认/驳回；低信息块在折叠区展示但不进入 provider payload。当前 `local_mock` 不生成日记事实或行动项，也不调用云端。

网页保存真值时会原子替换对应 JSONL，避免半写入文件。每个片段只更新允许的人工字段，模型导出文本、时间和片段 ID 不会被网页修改。

## 安全边界

- HTTP 服务只允许绑定回环地址，不对局域网或公网开放。
- 所有接口要求随机令牌或会话 Cookie；修改接口同时拒绝跨站来源。
- 页面使用严格内容安全策略，不加载第三方脚本、字体或图片。
- 音频回听按需从原始录音截取到 `outputs/`，不会修改原件。
- 时间轴单次最多生成 120 秒响度增强 WAV，缓存路径含会话源指纹和时间范围；原始音频永久只读。
- V2-E.0.1 本地底账保存文字、token/说话人证据和原音 SHA-256/时间坐标；单独的 provider payload 只含匿名化文字/时间/不确定性和 evidence key，不含音频、路径、原音哈希、数据库 token ID 或声纹 embedding。
- 语义交换和基础候选不可覆盖；网页修改写入独立的追加 revision。
- “确认”行动候选只改变本地 SQLite 状态，不连接系统日历。
