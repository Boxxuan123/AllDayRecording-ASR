## 1. 交付边界

V3.0-E 交付了独立的 Desktop Frontend 和 loopback-only Desktop API。V3 页面不再挂载
`workspace/controller.js`，不读取旧 DOM ID，也不把页面状态写入 Core use case。V2 源码、默认入口和
生产构建继续保留，直到 V3.0-G 才允许切换：

```text
all_day_recording_front/src/      V2 回退前端
all_day_recording_front/v3/       V3 独立 Vue 源码与 mock contract
src/allday_asr/web_assets/        V2 构建产物
src/allday_asr/v3/web_assets/     V3 构建产物
```

本阶段没有删除 V2 页面、改变 V2 API、下载模型、发布到外部主机或切换真实用户入口。

## 2. Desktop 架构

前端采用 History 路由、typed DTO/client、30 秒 query cache，以及独立的 route、connectivity、media
和 processing event 状态模块。V3 mock 由前端源码直接提供，不导入 Python，也不要求 Core 进程：

```text
Vue view/component
  → typed Desktop API client
  → query cache / SSE recovery
  → /api/v3 loopback interface
  → DesktopQueryService
  → UnitOfWork.desktop read projection
  → V3 SQLite / content-addressed audio store
```

统一 Media Controller 在整个应用中只创建一个 `Audio` 实例。切换媒体先停止旧源；会话详情切换、
组件卸载或离开页面时执行 pause、移除 `src`、load 和 identity 清空。页面只取得 `media_id`，绝对路径
不会进入公共 API。

处理中心以 SSE 消费 append-only processing change event；连接失败时立即用 REST 重新读取持久快照，
随后退避重连。页面重开和 Core 服务重启都从 SQLite 中的 job/run/stage/attempt 恢复，不构造前端任务
真相。

## 3. 页面与路由

| 路由 | 页面职责 |
| --- | --- |
| `/` | 会话、任务、备份与设备总览 |
| `/recordings` | 稳定 session ID 搜索、状态筛选和录音库 |
| `/recordings/:sessionId?tab=...` | 概览、utterance 时间线、原音、说话人、artifact/备份证据、run 历史 |
| `/reviews` | `waiting_review` 收件箱 |
| `/processing` | durable job 筛选、stage/attempt、取消与重试 |
| `/devices` | 配对、身份、最近活动与 revision |
| `/data` | 原音、副本、恢复演练、artifact 与 stale 健康度 |
| `/settings` | 只读展示本地部署、准入、保留和隐私策略 |
| `/lab` | 明确隔离且默认关闭的 Legacy/实验边界 |

普通主导航不包含 Lab，也不出现 benchmark 或实验术语。Lab 只能通过显式路由进入。录音筛选状态写入
URL；会话 ID 与 tab 均由路径/query 解析，因此直接打开或刷新嵌套详情不会依赖之前的内存状态。

所有数据页面共享 loading、error、empty 和 retry 边界；网络离线时显示本机数据仍可用与重新连接语义。

## 4. Desktop API 与安全边界

`allday-asr desktop` 启动专用 loopback server，默认监听 `127.0.0.1:8766`。启动链接中的随机 token
只用于换取 `HttpOnly; SameSite=Strict` Desktop Session；API 也支持专用 session header。写请求检查
same-origin，错误统一为 `code/message/details/request_id`，安全响应包含 CSP、禁止 framing、nosniff 和
no-referrer。

接口覆盖：

- status、overview、opaque keyset session page 和完整 session detail；
- durable job list/snapshot、run projection、retry/cancel、review inbox；
- devices、data health、只读 settings 和 Lab boundary；
- utterance optimistic-revision correction；
- `media_id` 到内容寻址文件的 HTTP Range 读取；
- 支持 `Last-Event-ID`/`after` 恢复的 processing SSE。

OpenAPI 已由骨架扩展到上述 V3.0-E 实际接口，recording session schema 增加 Desktop 查询投影字段；
manifest 与 Harmony consumer receipt 的 SHA-256 已同步。

## 5. 运行方式

独立 mock 开发：

```text
cd all_day_recording_front
npm run dev:v3
```

真实本机 Core：

```text
$env:ALLDAY_V3_ENABLED = "1"
allday-asr desktop --state-dir <v3-state-directory>
```

`npm run build` 会依次构建 V2 和 V3，保证并行期的回退入口仍可生产构建；`npm run build:v3` 只构建
V3 并输出到 Python package 内的独立资产目录。
