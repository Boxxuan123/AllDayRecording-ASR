## 已落地能力

Core 的 canonical utterance 同时保存：

- 会话内 `start_ms/end_ms` 与 UTC 绝对时间 `start_at/end_at`；
- 当前 `text/speaker_track_id`；
- 不随人工校正改变的 `original_text/original_speaker_track_id`；
- revision、状态与原音 evidence。

文本和说话人通过一次 correction operation 原子修改。调用方必须提交期望 revision；旧 revision 返回明确冲突，不会静默覆盖别人的修改。每次成功修改都会保留不可变 patch、追加 audit/change event，并只将依赖该 utterance 的下游 artifact 标为 stale。无变化、空文本、其他会话的说话人轨道和错误 payload 都会被拒绝。

Desktop 会话页展示绝对时间与模型基线，可同时修改文本和说话人。点击原音时，页面先定位覆盖该 utterance 的 capture segment，再把会话偏移换算为源文件偏移，避免多分片会话从错误位置播放。

Phone 使用同一 canonical DTO，离线修改先写入持久 outbox：

```text
utterance.correct
  + base_revision
  + utterance_id
  + text
  + speaker_track_id
```

下一次增量同步由 Core 使用与 Desktop 相同的校正服务处理。成功返回新 revision；冲突和拒绝结果保留在 Phone 冲突记录中。Phone schema 4→5 把 cursor 归零；旧格式 utterance 在运行时校验中不会进入时间轴，随后由 projection 2 的完整重放覆盖。本地原音、配对信息和待提交 outbox 不删除。

## 数据迁移

Core schema 3→4 重建 utterance 表并补齐 V3.1 字段。绝对时间由 recording session 的 `captured_start` 加会话偏移计算。原始文本优先取该 utterance 最早的历史 upsert change event，因此 V3.0 中已做过文本校正的记录仍能恢复模型基线；没有历史事件时才退回迁移时的当前值。

Device projection 从 1 升至 2 后，服务端已确认 cursor 归零，Phone 必须重新拉取完整可重建投影。旧 projection 数据不能与新 DTO 混读。

## 接口变化

- `GET /api/v3/utterances/{id}/corrections` 返回当前 utterance 与不可变校正历史。
- `POST /api/v3/utterances/{id}/corrections` 接收 `expected_revision`、`text`、`speaker_track_id`；revision 冲突返回 HTTP 409。
- `/device/v3/status` 与 `/device/v3/sync` 使用 projection `2`。
- Utterance DTO 新增 absolute time 和 original value 字段；Computer 与 Phone 的 fixture/hash receipt 同步更新。
