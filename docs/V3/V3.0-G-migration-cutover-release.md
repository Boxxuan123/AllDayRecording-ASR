## 真实 V2 数据迁移证据

源库为 `state/allday_asr.sqlite3`，schema `15`。迁移命令始终先从 SQLite 只读连接创建一致性快照，再从第一份快照运行 `LegacyV2Importer`，不会在原 V2 库上执行迁移或写操作。

```powershell
.venv\Scripts\allday-asr.exe release-prepare state\allday_asr.sqlite3 `
  --backup-a outputs\v3.0-g\backup-a `
  --backup-b outputs\v3.0-g\backup-b `
  --state-dir state\v3

.venv\Scripts\allday-asr.exe release-verify `
```

V2 明细并未伪装成一次新的 V3 模型运行。导入器把 `asr_alignment_tokens` 30,493 行、`asr_token_sources` 30,558 行、`diarization_turns` 3,858 行、`diarization_turn_sources` 3,984 行和 `token_speaker_attributions` 6,097 行保存为带 `legacy_ref`、内容 SHA-256 与行数的不可变 snapshot artifact；214 条人工修正另有不可变 correction operation。原生 V3 `utterances/speaker_tracks` 只在 V3 durable processing 执行后产生，真实导入本身不会伪造这些投影。

## 默认入口与回退边界

Desktop：

```powershell
# 默认 V3 Desktop
allday-asr web

# 明确进入 V2 只读网页；所有 POST/PUT 返回 405
allday-asr legacy web

# V2 命令必须显式使用 Legacy 命名空间
allday-asr legacy doctor
allday-asr legacy workflow --help
```

Phone 默认根页面直接装配 `PhoneV3RootPage`。缓存页提供“Legacy V2 只读资料”入口，只能浏览旧接收索引和播放本地原音，不提供同步、上传、删除或修改。

紧急回退使用 `ALLDAY_V3_ENABLED=0`，并明确调用 `allday-asr legacy ...`。回退不得降级或删除 V3 Core 数据库、Phone projection、release receipt 或双备份；恢复 V3 后继续使用原 schema 和 cursor。生产 Device listener 默认开启 V3，只有诊断时才允许 `--legacy-only`。

## 发布配置、配对与隐私

生产 Device listener 必须由发布环境提供真实值：

```text
ALLDAY_V3_DEPLOYMENT=production
ALLDAY_V3_PASSKEY_RP_ID=<与 App Linking/AGC 一致的真实域名>
ALLDAY_V3_PASSKEY_ORIGINS=<可信 ohos:app-id:... 或 HTTPS origin>
```

生产模式拒绝 IP、单标签主机、占位后缀和 RP ID/origin 不一致。首次配对继续使用 Passkey 登记 HUKS 设备公钥；后续上传与投影同步使用设备签名。撤销设备后不再签发新 challenge；清除手机本地缓存是独立用户选择，不由撤销隐式触发。

V3.0-G 没有新增云端 LLM、遥测或公网依赖。原音、数据库、备份、迁移 receipt、设备日志和签名构建产物均为本地敏感数据，不得提交 Git、发送到第三方或包含在普通问题报告中。
