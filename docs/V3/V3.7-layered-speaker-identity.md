# V3.7 四档人物声纹识别与防污染学习

冻结版本：Contract `3.7.0`、Core schema `11`、Phone projection `4`

## 决策分层

已知人物匹配不再使用单一阈值直接写入身份，而是对每条说话轨保存不可变决策：

1. `insufficient_evidence`：音频质量低于门槛，不展示人物结论。
2. `auto_matched`：人物已校准、用户已开启自动确认、分数超过自动阈值且与第二候选有足够间隔；允许自动关联身份。
3. `suggested`：超过建议阈值但不满足自动确认条件，只进入人工审核候选。
4. `no_known_match`：低于建议阈值，界面保持“其他人 / 未匹配已知人物”；最相似人物和分数仅作为内部审计、困难负例候选使用。

本人声纹继续使用独立的干净注册与校准策略，不与日常聊天学习库合并。

## 防污染学习

- 整簇关联人物只同步时间线身份、事件引用和人物记忆，不再批量注册簇内声纹。
- 声纹以单条 `prototype` 为审核单位。只有 `confirmed` 会产生稳定的、人工确认的 accepted prototype。
- `rejected` 是人物特定的困难负例；`uncertain` 保持待定；`retracted` 让已确认原型立即退出后续匹配。
- 原型、审核、匹配决策和人物策略均为追加式记录，保留完整审计历史。
- 确认、拒绝、撤回和策略改变后都会重新匹配仍未关联的历史声纹。

## 人物成熟度与自动确认

人物成熟度分为 `seed`、`learning`、`calibrated`、`suspended`。当前严格校准条件是：

- 至少 3 条人工确认正例；
- 正例来自至少 2 段录音；
- 至少 2 条人工拒绝负例；
- 跨录音留出验证召回率至少 80%；
- 当前自动阈值下负例误接收率为 0。

达到 `calibrated` 只代表具备前置条件，自动确认仍默认关闭。用户必须对该人物显式开启；若撤回样本导致校准失效，自动确认会随即关闭。

## V2 人工身份的最终迁移

旧库中的 `mother`、`father` 等人工身份不能只折叠成 `not_self`。在删除 V2
之前，必须显式执行一次：

```powershell
allday-asr legacy-speaker-backfill state\allday_asr.sqlite3 --state-dir state\v3
```

该命令只接受活动且人工确认的区间，排除短于 800 ms 或与其他身份标注冲突的
区间；然后按“人物 × 旧录音会话”从 V3 内容寻址音频重新提取当前 CAM++
embedding。结果保存为独立的 V3 人工声纹种子、人工人物链接和 `confirmed`
审核记录，不会把可能混有电视声或其他人的整个匿名簇批量登记。来源 ID 稳定，重复
执行只返回 `existing`，不会重复增加样本。

迁移完成后，人物匹配、成熟度计算、试听和历史重匹配只读取 `state/v3` 中的音频、
原型和审核记录。V2 数据库仅作为这条显式一次性命令的只读输入，不属于桌面服务、
手机同步或后续识别的运行时依赖。确认所有源会话均已映射且备份可恢复后，才可以在
单独的清理步骤中移除 V2 文件。
