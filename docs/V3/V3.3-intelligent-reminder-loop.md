# V3.3 智能提醒闭环

状态：工程实现完成

冻结版本：Contract `3.3.0`、Core schema `7`、Phone projection `4`

日期：2026-09-01

## 交付边界

V3.3 把对话证据转换为可执行提醒，但模型不拥有数据库写权限。Desktop 可由用户在提醒页调用 `POST /api/v3/reminder-generations/codex`，把所选会话的有效 utterance 文本交给 Codex；也保留 `POST /api/v3/reminder-generations` 供应商无关入口。两条路径都必须提交带模型、提示词、提取器和输入范围 provenance 的结构化候选，应用层再依次执行字段校验、证据校验、去重、目标事件与修订检查、冲突分类和确认策略。

Codex 复用本机已登录的 Codex 会话，不在项目中保存 API Key。每次提取使用独立临时 thread，工作目录是用户配置的专用空目录，并在 thread 与 run 两层强制 `read-only` sandbox、`deny-all` approval；提示词禁止命令、文件、网络、MCP 和子代理，运行结果中一旦出现任何工具活动就整次拒绝。发送内容只包含选中会话的 utterance ID、时间范围、说话人/身份标签和文本，以及同会话的活动提醒；不发送音频、数据库、项目路径或 Codex 工作目录。运行后目录必须仍为空。

`ReasoningEffort` 默认为 `auto`：短而直接的文本使用 `low`，普通提取使用 `medium`，超长上下文或带已有提醒的修改/取消语义才提升到 `high`；`xhigh` 只接受用户显式选择。无论模型置信度如何，Codex 自动应用默认关闭，候选先进入人工审核。

运行配置：

- `ALLDAY_V3_CODEX_WORKDIR`：专用空目录，默认 `~/.alldayrecording_codex`；空值或目录内已有文件时拒绝运行。
- `ALLDAY_V3_CODEX_REASONING_EFFORT`：`auto`、`low`、`medium`、`high` 或 `xhigh`，默认 `auto`。
- `ALLDAY_V3_CODEX_MODEL`：可选；不设置时复用本机 Codex 配置的默认模型。
- `ALLDAY_V3_CODEX_ENABLED=0`：关闭 Codex 入口，但不影响本地提醒审核和投影。
- `ALLDAY_V3_CODEX_AUTO_APPLY`：默认 `0`；当前产品边界不建议开启。

首版只接受六种操作：

- `CREATE_TASK`
- `CREATE_APPOINTMENT`
- `UPDATE_EVENT`
- `CANCEL_EVENT`
- `MARK_DONE`
- `IGNORE`

`IGNORE` 只表达“不采纳这个候选”，不会创建事件、提醒或长期记忆。更新、取消和完成必须引用已有 `target_event_id` 与期望修订；修订不一致时进入冲突状态，不会静默覆盖。相同会话、主体、标题和时间形成稳定去重键，重复候选不会生成第二个提醒。

## 确认与自动应用

默认路径是候选审核。只有同时满足以下条件才允许自动应用：

- 置信度至少 `0.98`；
- 候选显式声明无需确认；
- 行动主体为 `self`；
- 承诺方向是“我答应别人”或无方向任务；
- 时间完整、可解析且在未来；
- 所有引用 utterance 仍为有效证据；
- 证据的本人身份结论为 `self`。

任一条件不满足都会 fail closed，进入 Desktop 候选页等待用户确认、修改或忽略。用户修改会保留原候选、创建替代候选并记录不可变反馈，不覆盖模型原始输出。

## 事件与证据闭环

被接受的候选写入同一个事件的操作历史和当前状态，并创建或更新可执行 schedule。创建、改期、取消、口误修正和标记完成都沿用事件 ID，通过 revision 防止并发覆盖。

每个候选保留 utterance 证据引用。Desktop `/reminders` 页面可以查看候选字段、确认、编辑、忽略并播放原始音频片段。若用户随后修正证据并使派生结果失效，关联 schedule 会变为 `stale`，同步层发出 tombstone；错误提醒不会继续投影到 Phone，也不会被提升为长期记忆。

## Phone 与系统提醒

跨端只同步已接受的严格 reminder projection，未确认候选永远留在 Desktop 审核边界内。Projection `4` 会把旧 cursor 重置为 `0`，让现有已接受提醒按幂等 upsert 重新投影；Phone 本地 schema `7` 使用独立的 `projection_reminders` 表。

Phone 首页展示同步后的提醒。对未来且状态为 `scheduled` 的提醒，HarmonyOS 端使用 `reminderAgentManager` 发布可持久化日历提醒；更新同一事件时更新系统提醒，取消、完成、失效或远端 tombstone 会撤销对应系统提醒。应用声明 `ohos.permission.PUBLISH_AGENT_REMINDER`，并在需要时请求通知开关。用户拒绝通知权限或设备能力不可用时，调度错误被隔离，应用内持久提醒列表仍然可用，数据不会丢失。

## 接口与契约

Desktop 新增 Codex 生成、供应商无关生成提交、候选列表/详情/反馈、确认/修改/忽略、schedule 列表、到期查询和投递回执接口。Device 同步沿用 `/device/v3/sync`，但 `resource_type` 新增 `reminder`，服务端和 Phone 都在运行时校验严格 DTO；Desktop 内部查询可包含 delivery 元数据，因此不冒充严格的跨端 DTO。

## 已知限制

- 已接入 Codex 文本提取器，但仍依赖本机 Codex 登录与网络；未登录、运行失败、输出不合约或检测到工具活动时均 fail closed，不影响已有本地证据与提醒。
- 当前没有独立自然语言时间解析服务；模型必须返回带时区的绝对时间，应用层只做严格验证，不猜测模糊时间。
- 系统通知是否真正弹出依赖真机通知权限、系统能力和签名配置；权限失败不影响应用内提醒。
- 交付的是单次绝对时间提醒，尚未包含周期规则、复杂时区自然语言或多人共享日历。
