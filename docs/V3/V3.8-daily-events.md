# Daily events and structured summary V1

V3.8 extends the shared V3.2 event store and V3.6 daily summary revisions. It does not create another event/task system. Daily records use `important_experience` with a versioned daily payload. The anchor session identifies the record; evidence may span continuous recordings.

Local timeline → candidate windows → explainable adjacent merge → revisioned events → structured summary → V3 sync → Phone cache and evidence playback.

Candidates consider temporal gaps, explicit lexical topic/activity changes, participants and bounded windows. Adjacent windows merge through shared existing task IDs, explicit topics and participants, or continuous context within 90 seconds bounded to five minutes. Strong task/topic context is bounded to 20 minutes; a gap above five minutes always separates events. These are conservative V1 heuristics, not a semantic accuracy claim. Isolated fillers and fragments without at least four content characters or explicit task/topic signals are excluded. Titles quote source excerpts; discussed activities and completion are never inferred from fluent prose.

Evidence snapshots retain utterance/session IDs, source revision, time ranges, generation-time identity, original text and all capture/media range references. Existing evidence links and derivation dependencies provide revision invalidation. Reconciliation reuses event IDs through utterance overlap or physical source-range overlap, writes only changed revisions, and explicitly retires superseded automatic records. `manual_fixed` records are preserved; stale fixed evidence is omitted from current summaries pending review.

Task links reference existing task event IDs, including historical source evidence when the task changes. Summaries read current task state and schedule; creation/completion dates come from task history. No task, identity, profile, learning or Calendar write occurs. Known people come from existing identity references; unknown speakers retain track/cluster references. Missing confidence is represented as unknown rather than invented.

Structured summaries provide date, count headline, key events, created/completed/pending tasks, people, unresolved tasks, source event IDs and revisions, and local generation provenance. Every substantive item references events. Empty days contain no invented activity. V3.6 narrative compatibility is retained. Local rules make zero remote model calls.

Explicit desktop generation reconciles the selected day immediately. Receiver metadata sync refreshes historical source days and existing summary dates, with a 30-second rate limit across repeated pages. Late uploads use source timestamps, not arrival time. Events, summary and change-log publication are atomic per day. Phone database schema 19 adds two rebuildable projection caches without changing the existing cursor, audio bindings, outbox or Calendar mappings. Projection version 5 and Core migration 27 preserve acknowledged cursor progress. Summary source revisions prevent evidence from a different version being presented as matching.

Phone: More → Daily Summary → event evidence → existing utterance playback/session page. Desktop Insights adds event ranges, participants, task links, merge explanations, evidence playback and generation provenance. Offline content remains cached; empty, loading, read-error and incomplete-version states are explicit.

Private historical replay manifests, source snapshots, interactive feedback reports and data fingerprints live under ignored `outputs/`; none belong in Git. Feedback categories reserve the future review interface: OK, merge, split, incorrect person, incorrect summary, unimportant, missed event. V1 does not yet apply that feedback automatically.

Limitations: lexical rules can split one discussion or combine adjacent unclassified subjects. Source identity/ASR uncertainty remains visible. Salience is a deterministic ranking, not learned relevance. Event outcomes are not inferred; task completion requires authoritative task history. Background freshness follows receiver sync or explicit day refresh, not a separate scheduler.
