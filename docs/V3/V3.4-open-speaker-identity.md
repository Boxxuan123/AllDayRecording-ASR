# V3.4 未知说话人聚类与标注

开发状态：工程实现完成（2026-09-01）
冻结版本：Contract `3.4.0`、Core schema `8`、Phone projection `4`

## 完成边界

V3.4 将 `speaker_track`、匿名 `speaker_cluster` 与稳定 `person` 明确分离。原始
diarization artifact 和 utterance 基线不被聚类结果覆盖；自动分析只追加候选原型、
成员关系和操作记录。

用户从 Desktop“人物与声纹”页选择已处理会话后，Core 从内容寻址音频仓读取少量代表
片段，在本机用 CAM++ 生成 embedding。匿名簇采用保守余弦阈值和最小分差做录音内及
跨录音聚合；分数不足或候选接近时直接保留未知。与普通稳定人物原型的高分匹配只写入
“可能是”提示，不自动建立人物链接。唯一例外是已经通过 V3.1 独立留出集校准并验收的
本人声纹：高于本人阈值且轨道质量达标时可自动建立 `source=automatic` 的本人链接并同步
时间线；落在本人/非本人阈值之间时仍保持未知。

## 防污染规则

- 候选 embedding 保存在 `voice_prototypes(status=candidate)`，不会参与稳定人物识别。
- 本人自动链接不会把候选 embedding 晋升为稳定原型，避免一次自动判断污染注册声纹；
  已校准的独立本人声纹仍是自动判断的唯一参考。
- 只有用户执行“关联已有人物”或“新建并关联”后，候选才复制为
  `accepted + human_confirmed` 的不可变原型。
- 每个确认人物保留多个独立原型；匹配时使用这些原型形成的人物表示，但数据库不把
  它们破坏性压缩为唯一平均向量。
- 原型和人物操作均有 SQLite 触发器禁止 UPDATE/DELETE；纠错通过新链接、新操作和
  append-only undo 表达。
- 未确认人物簇、候选原型和代表音频不进入 Phone projection。

## 人工纠正

Desktop 支持关联已有人物、创建人物、合并匿名簇、按说话轨拆分、忽略电视/广播/
环境声，以及撤销最近一次有效人工操作。“暂无法判断”不需要任何写操作，匿名簇继续
保留并可在未来录音中获得新证据。

人物确认后，Core 搜索结构化事件 payload 中对该匿名簇的精确引用，以原事件修订号和
同会话 utterance 证据提交 `human-identity-correction` proposal，再通过既有 V3.2 事件
操作边界接受它。事件 current state 升版，旧 operation 历史保持可追溯。

## 本地与跨端边界

- 音频路径只存在于本机 adapter；API 和合同只暴露 `media_id` 与毫秒范围。
- CAM++ 在用户触发分析时延迟加载，Desktop 启动不加载模型。
- `ALLDAY_V3_SPEAKER_DEVICE=auto|cpu|cuda` 可选择本机执行设备。
- Core schema 从 7 升到 8；Phone projection 仍为 4，现有提醒和录音同步游标无需重置。

V3.4 不建立人物长期记忆、关系总结或跨天人物画像；这些属于 V3.5。
