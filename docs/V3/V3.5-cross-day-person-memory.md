# V3.5 跨天人物记忆

开发状态：工程实现完成（2026-09-01）
冻结版本：Contract `3.5.0`、Core schema `9`、Phone projection `4`

## 完成边界

V3.5 只为 V3.4 已确认的稳定 `person_id` 建立长期资料和记忆。匿名说话人簇仍然可以
跨录音积累证据，但在人工确认前不会拥有长期人物画像。人物页现在同时展示别名、关系
标签、首次与最近出现时间、跨天互动、共同话题、承诺、未完成事项和带证据的记忆。

事件层是自动投影的输入。`person_fact`、`commitment`、`request`、`task` 和
`appointment` 会确定性地投影为人物记忆；同一 `person_id + event_id` 使用稳定记忆
标识，事件升版、完成或取消后只追加新的记忆 revision。V3.5 不重新把全天原始转写交给
模型，也不生成 V3.6 的关系总结。

## 记忆类型与防永久化

人物记忆明确区分：

- `stable_fact`：稳定事实；
- `preference`：偏好；
- `short_term_state`：短期状态；
- `plan`：计划；
- `commitment`：承诺；
- `model_observation`：模型观察。

每条记忆都保存 `valid_from`、可选 `valid_until`、置信度、确认状态、来源和状态。
短期状态与计划没有 `valid_until` 时会被拒绝；模型观察固定显示为 `inferred`，不会
混入已确认事实。到期重算会追加 `expired` revision，而不是覆盖旧记录。

## 证据、修订与身份纠正

- 创建记忆至少需要一个结构化事件或一条 utterance 证据；
- 人物页可从记忆直接播放对应本地原话，API 只返回 `media_id` 和毫秒范围；
- 添加、修改、过期、撤回、恢复和身份迁移均写入不可变 revision 与 operation；
- SQLite 触发器禁止修改或删除人物资料 revision、记忆 revision、证据链接和操作历史；
- V3.4 人物重新标注时，只有证据 utterance 属于被纠正声纹簇的记忆才迁移；若撤回到
  未知身份，则相关记忆追加 `retracted` revision，等待未来重新确认和重算。

## 承诺与提醒

人物记忆可引用 V3.3 已接受的 reminder event。人物页同时展示承诺方向、提醒时间和
提醒状态；提醒仍由既有事件生命周期与 Phone projection `4` 执行。未确认人物记忆、
人物资料和模型观察不进入 Phone，仅已接受的提醒继续跨端同步。

## Desktop 能力

“人物与记忆”页分为跨天人物记忆和未知声纹聚类两部分。人物记忆部分支持：

- 修改显示名称、别名、关系标签和备注；
- 从当前事件层重算人物记忆；
- 展示跨天互动、共同话题和未完成承诺；
- 从证据事件添加事实、偏好、状态、计划、承诺或明确标记的模型观察；
- 修改、过期、撤回和撤销人物记忆；
- 回听每条记忆关联的原话。

V3.5 不生成每日总结、互动频率趋势或关系推断；这些仍属于 V3.6。
