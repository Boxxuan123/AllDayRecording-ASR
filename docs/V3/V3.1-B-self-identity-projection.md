## Canonical 身份模型

每条 utterance 新增三个字段：

- `identity`：当前的 `self`、`not_self` 或 `unknown`；
- `original_identity`：首次模型投影，人工校正不会覆盖；
- `identity_evidence`：不可变的模型来源、策略版本、校准集规模、FAR/FRR、窗口数量、分数摘要和拒绝原因。

身份和文本、说话人轨道共用同一个 correction revision、冲突检测、审计日志、change event 和下游 artifact 失效事务。人工修改当前身份时，原始身份与模型证据保持不变。Phone 离线 outbox 使用相同的 `utterance.correct`，payload 同时包含 `text`、`speaker_track_id` 和 `identity`。

匿名 speaker track 继续只表示一次处理 run 内的聚类。系统不会因为一条轨道中的某个窗口像本人，就把整条轨道全部绑定为本人；这避免了本人、家人、电视或重叠声污染同一聚类时的批量误标。

## 声纹判定门禁

V3.1-B 将已有余弦声纹分数接入版本化三态策略，但判定默认 fail-closed：

1. 校准集必须与 enrollment 会话隔离；
2. 默认至少需要 20 个本人正例和 50 个非本人负例；
3. 留出集 FAR 不高于 1%，FRR 不高于 20%；
4. utterance 至少有两个不短于 2 秒的干净窗口；重叠语音和媒体播放窗口不参与判定；
5. 所有干净窗口都高于本人阈值才输出 `self`，都低于非本人阈值才输出 `not_self`，中间区域保持 `unknown`。

阈值不是概率。证据中保留 min/median/max 分数而不伪造置信概率。上游 V2 模型快照可以携带已经过该门禁的 identity evidence；V3 adapter 会验证 evidence 的 decision 与首次身份一致后再写入 Core。

最终人工校准集合并迁移标注和一次性网页的新标注后，冻结为 25 个本人正例和 101 个真人非本人负例。旧声纹在该集合上的 FAR 为 0.99%，但 FRR 为 48%，因此按 fail-closed 规则拒绝发布；使用单个录音会话做适配后的候选同样因 FRR 55% 被拒绝，均未进入正式配置。

2026-09-01 使用 `data/voice` 中 20 条、总长约 404.8 秒的纯本人微信语音重建声纹。VAD 得到约 399.69 秒有效人声和 85 个候选 embedding，一致性过滤保留 82 个。独立留出集复测得到 AUC 0.9644、FAR 0.99%（1/101）和 FRR 8%（2/25），同时满足 FAR 不高于 1%、FRR 不高于 20% 的门禁。正式本人阈值为 `0.1376041621`，策略文件记录并校验所绑定声纹的 SHA-256；生产候选流程只在当前声纹哈希匹配时读取该活动阈值，否则回退到静态配置，避免声纹更新后误用旧阈值。

2026-08-31 已使用 `allday-asr label-migrate` 对旧库的冻结真值、人工身份区间、身份 reference、旧 segment 标注和声纹库做统一迁移与去重。完整迁移得到 281 条身份来源记录；按至少 2 秒、真人、非媒体、可追溯原音的标准，形成 13 个本人窗口和 57 个真人非本人窗口，另有 37 条电视/媒体记录进入独立鲁棒性集合。旧 enrollment 长音频继续用于建模，不能同时冒充独立 holdout；因此当前只需再补 7 个来自 enrollment 之外录音的本人窗口，而不是重标旧数据。

迁移命令只读旧数据库，并以内容哈希发布追加式标注包、收据和补标报告：

```powershell
allday-asr label-migrate state\allday_asr.sqlite3 --output-dir state\v3\labels
```
