## 1. 交付边界

V3.0-F 交付了并行的 Phone V3 工作台。它以 Phone 音频文件索引为本地事实源，以
`phone_v3_projection.db` 为可恢复的 Computer 投影和同步状态源，并通过已配对的
Device API 增量更新。Computer 不在线时，首屏、录音列表和本地播放不等待网络。

本阶段没有提前执行 V3.0-G 的默认入口切换。旧 Phone 首页、录音、Watch 同步、恢复、
Wi-Fi 快传和电脑上传路径继续作为默认界面；设置页提供显式的“V3 手机工作台（预览）”
入口。V3 工作台中的播放和 Watch 同步经受限 bridge 复用当前设备能力；只有组合根负责把
既有实例注入 bridge，首页、列表、详情、同步和缓存等业务页面不直接持有旧巨型 ViewModel。

## 2. 分层与依赖边界

新增实现按以下依赖方向组织：

```text
V3 Pages -> PhoneV3ViewModel -> UI reducer / PhoneV3UseCases
                              -> repository / local audio / remote / device bridge ports

PhoneProjectionRepository ----^    PhoneV3LocalAudioRepository ----^
PhoneV3DeviceRemote -----------^    PhoneV3LegacyBridge ------------^
```

- Pages 只通过 `PhoneV3ViewModel` 读取不可变替换的 UI state 和发出用户动作；
- UI reducer 独立处理本地就绪、缓存就绪、忙碌、成功、失败、设备变化和会话选择；
- use case 同时依赖 repository port 与 remote port，负责缓存查询、三源合并、outbox 提交、
  change 应用和 cursor 推进；
- remote adapter 只负责读取安全配对、按稳定 `receiver_id` 发现电脑和创建 Device API
  session，不持有 RDB；
- RDB repository 不持有页面或远端 client；
- local audio repository 每次从 `ReceivedRecordingStore` 的清单和磁盘恢复结果生成会话事实，
  不依赖 Computer 投影；
- device bridge 只暴露 Watch 同步、选择本地会话和播放控制，不把旧 ViewModel 暴露给页面。

最长的新增 V3 源文件低于项目的 500 行维护阈值；没有继续扩张现有 703 行
`PhoneRecordingViewModel` 或 427 行 `PhoneComputerTransferViewModel`。

## 3. 本地优先启动与三源合并

启动顺序固定为：

1. 从 Phone 文件目录恢复本地音频清单并立即发布本地会话；
2. 打开 RDB，读取 recording、processing run、utterance、local link、conflict 和 sync state；
3. 读取是否已安全配对，但不发现电脑、不建立网络连接；
4. 按 `session_id` 或稳定 `session_key` 合并本地音频、Computer 会话投影和处理投影；
5. 只有用户点击同步或重建时才通过 mDNS 与 Device API 连接 Computer。

合并结果保留 Phone 本地路径、大小、时长和接收时间，同时展示 Computer 的 session
revision、聚合状态、处理 stage/progress 和最后更新时间。Computer 投影缺失时生成
`phone_only` 会话；本地文件缺失时仍可显示只读 Computer 投影，但不会假装可以离线播放。

上传 ingest 的 recording session projection 现在发布原 manifest `session_key`。Phone RDB
schema version 3 为 `local_audio_links` 增加持久 `session_id` 并建立索引；首次收到带
`session_key` 的 session change 时把本地链接绑定到 Computer `session_id`。后续状态
projection 即使不重复发送 session key，也不会丢失跨端关联；重建投影不会删除本地链接。

schema version 4 为异常终态留档增加 `status`。`conflict` 与 `rejected` 都在删除 outbox
前保留原 payload、error 和终态；重放按 operation ID 覆盖同一留档，不生成重复记录。

| 页面 | V3.0-F 能力 |
| --- | --- |
| 首页 | 本地优先最近会话、Watch 状态、会话/待同步计数、三段链路摘要、最后更新 |
| 录音列表 | 本地音频与 Computer projection 合并列表、离线播放标识、revision/更新时间 |
| 会话详情 | 本地播放、Watch→Phone、Phone→Computer、Computer processing 三段状态 |
| 只读时间线 | 显示 `utterance_id`、`revision`、时间范围、文本与 evidence JSON |
| 同步中心 | 配对状态、cursor、outbox、retry/error、增量同步、投影重建、电脑连接入口 |
| 缓存与冲突 | 持久离线状态摘要和 conflict receipt/error 列表 |
| 电脑连接 | 复用既有 CA 固定、Passkey、HUKS、mDNS、幂等断点上传页面 |

时间线身份始终使用服务端 `utterance_id`，revision 只作为可变版本显示；这为 V3.1 编辑
保留“内容变更但主键不变”的约束。

## 5. 同步、恢复与错误语义

`PhoneV3UseCases.synchronize` 先校验 contract/projection version，再读取持久 outbox 和旧
cursor；第一批同时提交操作并拉取 change，后续批只继续 pull。每个响应继续沿用 C 阶段的
receipt → change → cursor 单事务应用，cursor 最后发布。失败会持久记录 RDB error 和 retry
count，页面保持本地音频及上次缓存可读。

投影重建只清空可从 Computer 恢复的 projection/tombstone 并把 cursor 复位到
`cursor-0`；outbox、conflicts、local audio links 和安全配对保持不变。音频上传仍使用现有
服务端 offset 协商：应用重启后重新查询同一上传身份的已验证 offset，不把进程内进度当作
事实，也不会重复提交已经验证的文件。

## 8. 阶段结论

V3.0-F 的 Phone 分层、页面、本地优先恢复、投影合并、三段状态、只读时间线、同步中心、
缓存/冲突和旧设备能力 bridge 已完成工程实现。自动化可证明的边界与恢复语义均通过；当前
没有连接真实 Phone/Watch，因此飞行模式、杀进程、Computer 恢复、真实播放和 Watch 5
回归仍不能标记为产品验收完成。V3.0-G 可以在完成这些真机证据后切换默认入口和执行跨端
发布验收，不能仅凭预览入口和 host tests 宣告发布完成。
