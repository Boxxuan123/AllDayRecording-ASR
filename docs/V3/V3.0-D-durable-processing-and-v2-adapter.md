# V3.0-D 持久处理编排与 V2 Adapter 验收

> 状态：工程实现完成（2026-08-31）
> 前置阶段：[V3.0-B Core Data 与 Legacy Import](V3.0-B-core-data-and-legacy-import.md)
> 并行依赖：[V3.0-C Device Gateway 与 Phone 本地数据层](V3.0-C-device-gateway-and-phone-projection.md)
> 规格：[V3 重构规格](V3重构规格.md)

## 1. 交付边界

V3.0-D 将 V3 处理路径从网页进程内任务状态中分离出来，建立以 SQLite 为唯一事实源的
可恢复 processing DAG：

- 命令先创建 `ProcessingRun`、`Job` 和完整 `StageRun`，随后 worker 才能 claim；
- 每次执行都有独立 `Attempt` 与带随机 token 的 `Lease`，心跳同时保存 checkpoint；
- 超时 lease 显式进入 `lost_lease`，重启后的服务可回收并从最后 checkpoint 创建新 attempt；
- 同一 session、input revision、pipeline version 只有一个有效 run；相同配置重放返回原任务，
  不同配置被拒绝；
- Admission 只有在 manifest、连续 segment、可用原音副本以及独立备份恢复演练证据都存在时
  才允许提交；
- 现有 V2-C/D/E workflow 通过 adapter 运行，其 token、speaker turn、utterance 与原音坐标
  冻结为不可变 V3 artifact，再投影为稳定的 speaker/utterance 资源；
- utterance 修改追加 correction 和 artifact stale event，只失效直接依赖制品，不重跑录音导入
  或无关阶段；
- processing run 与 utterance 的 revision 变化进入 change log，可由后续 Desktop 查询和既有
  Phone projection contract 增量消费。

本阶段不删除或改写 V2 workflow，不把模型实现引入 V3 domain/application，也不自动删除任何
原音或备份。真实数据切换仍属于 V3.0-G。

## 2. DAG、状态与恢复语义

默认 DAG 顺序固定为：

```text
ingest_verified
→ backup_admitted
→ window_plan
→ speech_gate
→ asr_and_alignment
→ diarization
→ utterance_projection
→ semantic_evidence_optional
→ mobile_projection
```

`semantic_evidence_optional` 失败会保留错误与 attempt 历史并继续完成 DAG；其他 stage 失败会使
任务进入 `failed_retryable` 或 `failed_final`。retry 不复写旧 attempt，而是将失败 stage 重新排队，
下次 claim 创建递增 attempt number。取消运行中任务先写 `cancel_requested`，worker 在心跳/checkpoint
安全点确认后释放 lease 并进入 `cancelled`。

schema version 3 增加：

| 表 | 用途 |
| --- | --- |
| `processing_jobs` | 持久队列、优先级、可执行时间和任务终态 |
| `stage_runs` | DAG stage、顺序、可选性、进度与输出摘要 |
| `stage_attempts` | 每次执行的配置、checkpoint、日志、错误和终态 |
| `worker_leases` | claim token、心跳、到期和释放/丢失事实 |
| `backup_evidence` | 独立设备/网络备份与恢复检查证据 |
| `speaker_tracks`、`utterances` | V2 证据到稳定 V3 资源的投影 |
| `artifact_dependencies` | artifact 对 utterance revision 的显式依赖 |
| `artifact_status_events` | append-only 的 stale 状态变化 |

`backup_evidence`、artifact、依赖与状态事件都受不可变约束保护。`processing_runs` 新增正整数
revision，每次可见状态变化递增并随 change event 发布。

## 3. V2 Adapter 与 Admission

`ExistingV2QualityWorkflowExecutor` 复用现有 session-native quality workflow，并读取已提交的
V2-C token、V2-D speaker turn 与 V2-E utterance evidence。adapter 校验每条时间范围以及 token、
turn、utterance 携带的原音 source reference，将完整快照按 canonical JSON 写入内容寻址 artifact
store；后续 stage 只读取该不可变快照，不重新解释可变 V2 数据。

原生 V3/Phone session 通过 `V2SessionMaterializer` 生成隔离的 V2-compatible manifest/audio view，
再以现有只读/幂等导入边界供 workflow 使用。已有 legacy V2 session 直接解析回原 V2 ID。兼容层不会
把 V2 表名或算法版本提升为 V3 领域概念。

`FilesystemSessionBackupAdapter` 将 manifest 与原音复制到调用者声明的独立设备或网络目录，逐文件
校验 SHA-256，并从备份重新读取计算恢复摘要。备份根与 V3 audio/artifact store 重叠时直接拒绝；
只有恢复检查成功的 append-only evidence 才能通过 Admission。

## 4. 运维入口

V3 仍需显式设置 `ALLDAY_V3_ENABLED=1` 并使用隔离 state 目录。标准顺序为：

```text
allday-asr v3 backup-admit <session-id> --backup-root <independent-root>
allday-asr v3 process-submit <session-id> --pipeline-version v3-v2-adapter.1
allday-asr v3 worker --once --v2-backup-root <existing-v2-backup-root>
allday-asr v3 process-status <job-id>
```

恢复和控制入口为：

```text
allday-asr v3 process-recover
allday-asr v3 process-retry <job-id>
allday-asr v3 process-cancel <job-id> --reason <reason>
```

production worker 必须提供既有 V2 workflow 所要求的独立备份根；`--shadow` 只用于影子验证。
服务或 worker 非正常退出后先运行 recover，或直接启动 worker（worker 每次 claim 前会自动回收过期
lease）。

## 5. 验收证据

| 规格验收项 | 自动化证据 | 状态 |
| --- | --- | --- |
| 提交即持久；重启可恢复或显式 lost lease | 重建 `DurableProcessingService` 后回收过期 lease，旧 attempt 为 `lost_lease`，新 attempt 从 checkpoint 恢复 | 通过 |
| 重复有效 run 不并行 | 相同 identity/config 返回同一 job；相同 identity 不同 config 被拒绝 | 通过 |
| V2 fixture 数量与区间一致 | 固定快照验证 2 token、1 turn、1 utterance、100–600 ms 及原音 100–600 ms source reference | 通过 |
| stage 失败不改原音/备份/已完成 artifact | 注入 diarization 失败，核对 audio replica、备份 digest/status 和先前 artifact 不变 | 通过 |
| retry 新建 attempt，历史可查 | 同一 stage 保留 failed/succeeded 两个 attempt，旧配置、日志摘要与错误均可查询 | 通过 |
| utterance 修改只失效依赖 artifact | correction 只产生一个 stale event；attempt 数、备份、原音与已成功 job 状态不变 | 通过 |

自动化门禁：

| 门禁 | 结果 |
| --- | --- |
| D/migration/repository 专项 | 16/16 通过 |
| `python -m pytest tests -q` | 213/213 通过；仅有不可写 pytest cache 警告 |
| `python -m ruff check src tests` | 通过 |
| CLI help/smoke | durable processing、backup、recover/retry/cancel/worker 命令均可发现 |
| `git diff --check` | 无 whitespace error |

固定 fixture 证明 adapter 的映射不变量，但本阶段没有下载模型或对真实生产音频执行 V2-C/D/E；
真实会话的模型结果、耗时与跨端展示属于 V3.0-G 纵向验收，不在此伪报为已完成。

## 6. 阶段结论

V3.0-D 的持久队列、DAG、attempt/lease、心跳 checkpoint、超时恢复、取消/重试、Admission、
V2 adapter、不可变 artifact、speaker/utterance 投影和选择性失效均已完成工程实现。V3 processing
路径不再依赖网页进程内 `JobRegistry` 作为事实源；V3.0-E 可以直接查询 durable state 并订阅其
change event，不能另建前端模拟任务状态。
