# V3.6 每日总结与关系观察

冻结版本：Contract `3.6.0`、Core schema `10`、Phone projection `4`

## 完成边界

V3.6 在 V3.2 的证据/事件层和 V3.5 的稳定人物资料之上增加两类 Desktop-only
派生资源：每日总结和关系观察。客观统计由本地程序计算；Codex 只负责语言归纳，不能创建
事件、人物、统计值或证据引用。

每日总结每次都从目标日期的当前事件层、人物互动、任务状态和少量关键原话重新构造输入，
不会读取上一版总结，也不会用“昨天总结续写今天总结”。关系观察使用明确的 `7` 天或
`30` 天窗口，已验证事实和模型观察分别保存、分别展示。

## 数据与修订模型

- `daily_summary_revisions`：按 `date + timezone` 保存不可变修订。
- `relationship_observation_revisions`：按人物和时间窗口保存不可变修订。
- `insight_evidence`：把每一版结果绑定到允许的事件与原话证据。
- `insight_operations`：记录生成、修改、撤回与恢复，不覆盖历史版本。
- `generation_records` 与 derivation dependency：保存模型、输入哈希、推理档位和来源依赖；
  底层事件或原话被纠正后，现有结果会变为 `stale`，重新生成会追加新 revision。

Core schema `10` 只追加新表、索引和不可变触发器。Phone projection 继续保持 `4`，每日
总结、关系观察、提示词和模型输出均不跨设备同步。

## 每日总结

程序先生成客观统计，再让 Codex 输出八个固定叙事分区：

1. 今天发生了什么；
2. 今天做出的决定；
3. 新增待办；
4. 已完成事项；
5. 未解决问题；
6. 重要人物互动；
7. 值得记住的话；
8. 明天需要关注什么。

每条叙事必须至少引用一个本次输入内的 `event_id` 或 `utterance_id`。模型返回不存在或
不在本次输入集合内的证据 ID 时，整次生成失败且不保存部分结果。

## 关系观察

本地程序确定性计算互动次数、互动天数、主要话题、未完成承诺与协作事项等已验证事实。
Codex 输出的观察必须包含文本、置信度、理由和证据。Desktop 页面将两者分栏，避免把
“可能更关注交付”等归纳伪装成事实。

用户可以修改观察、撤回整份观察或恢复最近一次撤回。所有操作都追加 revision；修改时
仍只能使用原报告已有的证据集合。

## Codex 隔离与推理档位

V3.6 复用 V3.3 的 Codex 配置：

- `ALLDAY_V3_CODEX_ENABLED`：控制 Codex 生成入口。
- `ALLDAY_V3_CODEX_WORKDIR`：必须是专用空目录。
- `ALLDAY_V3_CODEX_MODEL`：可选，未指定时使用本机 Codex 默认模型。
- `ALLDAY_V3_CODEX_REASONING_EFFORT`：`auto`、`low`、`medium`、`high` 或 `xhigh`。

`auto` 会根据输入规模和任务复杂度按需选择推理档位。每次生成都在空工作目录、只读
sandbox 和拒绝审批模式中运行；请求不包含音频字节、本地路径、旧总结或旧关系观察，且
运行期间出现工具活动会被视为失败。

## Desktop API 与页面

- `GET/POST /api/v3/daily-summaries[/{date}|/generate]`
- `GET/POST /api/v3/relationship-observations[/{id}|/generate]`
- `POST /api/v3/relationship-observations/{id}/revise`
- `POST /api/v3/relationship-observations/{id}/retract`
- `POST /api/v3/relationship-observations/{id}/undo`

`/insights` 页面支持日期、时区和推理档位选择，展示客观统计与叙事、7/30 天人物关系
窗口、证据回听以及修改/撤回/恢复操作。模型不可用返回服务不可用；生成失败不留下可见
资源；用户输入错误返回客户端错误。

## 自动化验收

- 每日生成的模型输入只来自事件层，不包含旧总结。
- 客观统计由程序计算，`auto` 能为小输入选择低推理档位。
- 虚构证据引用被拒绝且不会持久化。
- 底层纠正使旧结果过期，重新生成产生新 revision。
- 关系事实和模型观察分开，修改/撤回/恢复保持不可变历史。
- Codex adapter 固定空目录、只读 sandbox、拒绝审批和严格结构化输出。
- Contract manifest、OpenAPI、JSON Schema、Desktop bundle 与 HarmonyOS 消费收据一致。

V3.6 的完成声明只覆盖工程实现与合成数据回归。真实全天数据上的摘要覆盖率、遗漏率、
关系观察准确率和用户校正成本仍需独立人工评测，不能从结构化输出约束推导为内容正确。
