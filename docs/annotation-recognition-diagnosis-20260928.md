# 人物标注为什么没有明显改善识别

> 本文记录 2026-09-28 的历史诊断，统计、开关和代码行为均以当时为准。后续进展见 [Benchmark V2](speaker-recognition-benchmark-v2-20260928.md) 和 [Phase 4](speaker-verification-phase4-20261001.md)，下文候选重构方案不等于当前实施计划。

检查日期：2026-09-28。范围：Computer V3 当前代码、正式数据库只读事务、Phone 声音审核入口和后台日志。

后续更新：同日已完成离线可行性实验，见 `annotation-feasibility-pilot-20260928.md`。实验支持优先改善校准和数据一致性；三种多片段匹配方案均未优于重新校准的平均声纹。下文重构方案保留为诊断阶段候选，不应直接作为开工决定。

## 结论

担心有依据。标注已保存，样本提取任务也在运行，部分已采纳声纹确实进入了匹配。但目前熟人自动识别被校准条件和开关完全挡住；样本选择又让大量新增标注无法增加声音覆盖，并且发现了真实的正负样本冲突。

建议做**人物声纹学习与校准模块的局部重构**，先修明确缺陷，再改样本选择和校准。无需重写整个系统，也不是重启服务、补跑一次或改一个阈值就能解决。

本次没有修改业务代码、正式标注、声纹策略或运行服务。诊断脚本只读取正式库，计算使用已保存向量；未重新运行音频模型。

正式库保存了 1283 条历史匹配决策，包括 210 条 suggested，0 条 auto_matched；这些是重复重匹配累积的审计记录，不能作为独立音频识别率。对当前 22 个可重匹配原型，用生产决策函数只读重算，得到 21 个低于建议阈值、1 个质量不足，0 个建议、0 个自动确认。

本人另走独立库：533 条有效本人事实不会自动进入本人注册库。当前独立 matcher 可用、自动本人识别已启用、包含 82 个参考向量。这不代表当前所有场景的本人识别效果已验证。

## 二、主要问题

### 1. 自动识别的校准是固定门槛检查，没有根据数据求阈值

`people_prototypes.py::_refresh_maturity()` 读取固定自动阈值 0.92，计算跨录音正例召回和负例误接收，然后判定是否 calibrated。当前人物默认建议阈值均为 0.82，自动阈值均为 0.92。代码没有在此流程中拟合适合当前人物和场景的阈值。

实际可用正例各自寻找“另一录音中最相似的同人物样本”，最高分范围为：

| 人物 | 跨录音最佳同人物分数范围 | 在 0.92 下的正例命中 |
| --- | --- | --- |
| 张卫平 | 0.712–0.865 | 0 / 5 |
| 方庆声 | 0.468–0.740 | 0 / 4 |
| 母亲 | 0.611–0.899 | 0 / 15 |
| 父亲 | 0.733–0.760 | 0 / 4 |

所以并非“样本数量够了就会开启识别”。当前连这些已采纳正例之间的跨录音比较都达不到 0.92；部分人物又没有至少两条人工拒绝负例。即使以后通过校准，还需要显式开启自动确认。当前所有熟人都不满足自动确认条件。

这些分数是余弦相似度，不是身份正确概率。本次未验证人工真值，也不能仅凭这些分布给出可上线的新阈值。

### 2. 母亲的校准集存在同原音的相反审核

发现下面两个 prototype 的五个原音窗口完全相同，只有 utterance ID 不同：

- `01M1EAWSW8DBYC6J8ZS2R8WSNE`：2026-09-02 被 rejected。
- `01M1EAWSW9PTQZ5JM754K9T68T`：2026-09-02 被 confirmed。

两者向量相似度为 **0.9960117**。当前校准同时把它们作为母亲的负例、正例，因此出现 1 / 4 的负例误接收。这足以阻止校准，并不是声音模型证明“认错了一个独立陌生人”。

校准正例主要按 source_prototype_id 去重，审核也是 prototype 级别，没有在这个入口统一按原音范围检测相反结论。同一原音经重处理产生不同对象后，冲突会被当成两个独立样本。

需先把冲突标记为待核对并排除出校准，保留两条历史审核；不能自行判定哪个人工结论正确。调低阈值不会解决此冲突。

### 3. 标注数量远大于真正被抽到的声音范围

`annotation_sample_plan.py` 当前按“人物 × 录音会话”合并标注，从合并范围中按时长取最多 5 个窗口，每个最多 8 秒，再由 provider 求平均向量。一个会话的当前样本最多使用 40 秒。

例如张卫平的 2604 条事实，在当前 5 个样本集中只选了 200 秒，所选窗口引用 19 条事实。庞乾静的 258 条事实只选了 40 秒，引用 3 条事实。这不表示其余标注丢失：其余事实仍修正原句身份、参与范围冲突检查；但未选中的声音不会贡献该样本向量。

当已有足够长的窗口时，继续标同一录音里的短句，可能根本不改变选中的音频和声纹。增加大量标注未必带来声纹变化，是当前设计的直接结果。

该 provider 的 quality_score 仅按选中时长 / 12 秒计算并截断至 1，未直接衡量重叠讲话、噪声或不同片段声音是否一致。把多个片段直接求平均，也无法保证得到的是同一个干净人物的代表声音。这些是设计局限；本次没有回听全部音频，不能据此断言每个样本受到污染。

### 4. 保存人物、采纳声音、校准、自动确认分成了多个步骤

这套防污染思路有价值：给原句确认人物，不应自动让整条混合说话轨成为声纹。但用户需要明确看到每一步的结果与阻塞原因。

当前确有“是他，采纳样本”的手机入口和桌面校准说明，并非完全没有流程；问题在于标注数量、已抽取声音、真正参与匹配、校准失败原因之间缺少直接反馈。母亲的同原音正负冲突、本人不进入日常学习库，都不能靠一个“已同步/已采纳”说明清楚。

黄鑫和陈泰杰当前选中时长分别只有 5.93 秒、4.96 秒，也达不到默认 0.5 质量门槛所隐含的 6 秒；他们还没有可参与匹配的已采纳原型。

### 5. 失效、校准更新、历史重匹配缺少统一持久任务

审核采纳后，代码先提交审核，再刷新成熟度，再同步执行历史重匹配。后两步若失败，没有与审核原子提交的专用后续任务来保证最终完成。

来源事实变动能使样本立即退出匹配，但 `_refresh_maturity()` 只从声音审核入口调用。实际已看到父亲策略记录 positive_count=5，当前可用正例只有 4 个。这个例子暂未误开启自动确认，但说明策略统计可能落后于实际样本状态。

这一项是代码层面的可靠性缺口，不能据此声称现有全部重匹配都失败了；本次数据证实历史重匹配确实发生过。

## 三、修改方案与范围

### 第一阶段：修正数据一致性与反馈，范围小到中等

1. 在审核和校准入口建立统一原音身份：使用原音摘要/媒体及窗口、预处理版本标识声音范围，避免只按 prototype/utterance ID 判断独立性。
2. 对相同、重叠原音的正负审核做冲突检测；同标签去重，相反标签挂待核对。迁移只新增冲突记录，不覆盖人工历史。
3. 合并实际匹配和校准使用的样本有效性条件，统一模型版本、质量、撤回、来源有效性判断。
4. 增加人物状态摘要：事实数、独立原音数、可用声纹数、覆盖录音数、最近更新、具体未启用原因。用户应能直接看到“卡在重复原音冲突/缺负例/分数不达标”。

验收：同原音相反审核不能同时进入正负校准集；无效样本退出后，人物统计和策略及时更新；现有人工身份不被迁移改写。

### 第二阶段：调整声纹构建，属于局部重构

1. 从单一“人物 × 会话平均向量”改为可追溯的片段向量及少量代表样本，保留原音定位与版本。
2. 选择样本时兼顾不同录音时段、声音条件和向量差异；去掉重复音频，优先补充已有样本不能覆盖的声音。保留容量上限，避免把所有标注无差别加入。
3. 增加单人声音一致性、有效语音、重叠和噪声检查；具体指标和模型开销先通过小规模实验选择。
4. 保留“确认原句人物”和“用于声音学习”的区别，但可在同一操作中明确表达两个意图。清晰、可信的原音在用户选择用于学习后进入质量筛选；模糊和冲突样本集中审核，减少重复劳动。
5. 本人仍保留独立正式库，可新增候选适应库；通过独立验证后再更新正式策略，使日常本人标注有可见的利用路径。

验收：一条质量合格且代表新声音条件的标注，能够改变代表样本集合；冗余或不合格标注明确显示未加入的原因。整段人物关联不能偷偷扩大为整段声音学习授权。

### 第三阶段：实现数据驱动的校准，范围中等

1. 将建库、阈值选择、最终测试分开；按真实对话/日期隔离，手机和手表同时录到的同一对话不能分属不同集合。
2. 对固定模型及预处理版本统计同人物、不同人物分数，选择建议阈值和自动确认阈值；样本不足时使用已验证的公共策略或保持建议模式，不能假装完成了人物专属校准。
3. 审核为另一明确人物的干净样本可构成负例；“有点不像/不确定/有混音”不应等价为可靠负例。主动推荐有区分价值的少量核对样本，避免让用户盲目凑负例数。
4. 同时报告识别召回、陌生人误认、候选区分度和样本量；零次观测误认不等于真实误认率为零。自动确认仍由用户按人物启用。

验收：在独立对话上减少熟人留未知，同时控制误认陌生人。最终阈值由验证结果确定，本次不预设 0.70、0.80 等上线值。

### 第四阶段：补齐持续更新和端到端验收，范围中等

1. 样本采纳、撤回、来源失效、模型变更时，在同一事务中写入人物更新任务。
2. 后台按版本执行“更新有效库 → 校准 → 重匹配 → 更新下游引用”，支持幂等、失败重试和过期任务作废。
3. 对自动关联的旧身份定义失效/待复核策略，保留人工确认事实；当前重匹配仅处理未关联簇，不能把这等同于所有历史自动结果均已重算。
4. 不重跑全部 ASR：优先复用已有音频、向量和有效时间线，只有声音范围/模型改变时重新提取受影响样本。
5. 输出同一固定测试集的改前/改后结果，并展示每个人的增益、退步及所需人工审核量。

## 四、哪些设计可以保留

- 原音不可变、人工事实可追溯、审核可撤回。
- 低证据不强行给人物结论，建议与自动确认分开。
- 模型预测不会自动成为可信训练样本。
- 现有音频存储、标注同步、ASR 主流程与手机录音架构。

最有价值的下一步是先解决同原音冲突和校准真实性，再改代表样本选择与更新链路。继续按现在方式堆标注，收益很可能很低。
