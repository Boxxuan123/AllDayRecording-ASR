# Recall release stability gate

Run `python tools/quality/check_recall_stability.py --output <local-audit-folder>`.
It uses the normal composition, candidate/source expansion, evidence selection,
executor request packing, short-reference decoding and conclusion validation.
It invokes no real model and makes no real source requests. Synthetic claim
probes only exercise the protocol; passing them is not semantic acceptance.
The same tests are automatically collected by the normal full pytest suite.

The stage receipt records source-returned, application-accepted, actual model
input and final-citation IDs for renamed relationships, transferred bridges,
chat-density interference, shuffled source rows/paginated directories, daytime
plans, unknown evidence and invalid references. All executed requests must fit
the executor byte limit. Affirmative message periods still have to agree with
the source; dated comparison objects do not assert an utterance period.

Private real-source replay, independent question seals, answers, account IDs,
SDK receipts, model budgets and phone screenshots belong outside the repository
in a restricted audit directory. An evaluator must freeze its rubric before
running independent questions. Only the question and normal user state may
reach production retrieval. Once a question is observed it is an exposed
regression, not an unseen generalisation measurement.

Real release acceptance also requires bounded model accounting, default
permissions/configuration, real phone original/context navigation and restart
reuse. Keep the deployed baseline when those gates are not met. Never install
native test modules over the user's signed App or clear its data to get a test
result.

The same gate also covers native sender metadata discovery across separately
question-named rooms, independent same-name accounts, short quoted semantic
leads, and two temporally separate topical contexts. Sender discovery reads
only bounded authorised message pages through the existing API; it does not
write person mappings or maintain another message store. Source locators must
agree with the native platform/account/conversation fields. Replayed SDK
outputs remain protocol checks, never new semantic successes.
