# Windows 聊天查询 V1

最新状态：**CHAT_QUERY_V1_READY（2026-10-10，固定三会话与20题小样本）**。Mac 1.0.1 后原确切范围完整分页、快照/增量衔接和真实引用已复验通过。12次已授权真实模型响应及8个无证据回答已核对，原话排版修复以相同真实响应本机重放验证，未追加调用。详见 [最新复验报告](CHAT_QUERY_V1_RETEST_20261010.md)；[首次验收报告](CHAT_QUERY_V1_ACCEPTANCE.md) 保留当时的阻塞记录。

## 使用

在现有 V3 工作台导航打开“聊天查询”（`/chat`）。普通搜索不调用模型。默认最近 30 天；平台、采集账号、会话、发送者账号和日期可以共同筛选。账号和会话用稳定 ID，显示名仅用于显示，不按同名合并真实人物。目录每页 100 条，可继续加载。

关键词按区分大小写的 Unicode 字面子串查询。中文短词、连续短句、英文缩写、数字、文件名以及 `% _ ' "` 保持字面含义。点击结果打开完整原文、有限前后文、引用和附件元数据；返回结果保留当前筛选和已加载页。

选择“仅查本地缓存”会明确标为局部结果；对应回答也只用缓存。远端超时、鉴权错误和游标失效不会悄悄变为空查询或被当成完整缓存结果。Mac 离线时普通首屏可以退到缓存；远端分页中断需重新从缓存首屏查询，不能混用两种游标。

## 连接配置

可在聊天页的“Mac 连接配置”输入地址和同 Mac 一致的至少 32 字符 ASCII 凭据。保存位置为 `<V3 状态目录>/chat/connection.json`，默认 `state/v3/chat/connection.json`。整个 state 目录已被 Git 忽略；配置响应不返回凭据。不要把实际配置文件提交、上传或粘贴到公共报告。

也可以在启动工作台的同一 PowerShell 会话设置 `CHAT_DATA_BASE_URL` 和 `CHAT_DATA_TOKEN`；参照根目录 `config-chat.example.env`，不要在该样例里填真实凭据。环境变量优先于私有文件。`$env:` 只影响当前终端及其子进程，设置持久用户环境变量后，已经运行的工作台需重启才能继承；本轮已核实这个区别。私有文件配置不依赖 Codex 进程重新继承环境。

后端代码更新后，按项目原有方式重启工作台再打开 `/chat`。本轮没有为发布聊天查询终止原有手机接收、采集或录音模型作业。

## 范围、同步与恢复

指定平台、采集账号和会话后，点击“缓存此会话范围”。最多启用 5 个会话，优先最近 30 天。每页最多 100 条，单轮后台扫描有 60 秒/10 页每范围预算，每 30 秒续接已登记范围；没有自动扩大到多年历史的任务。

首批初始化缓存使用 5000 条保守预算，超出时显示 WORKSET_BUDGET_REACHED 和未完成快照，并暂停扩大范围。该限制不限制 Mac 原始库、远端历史关键词查询或用户按需获取的证据。**已经完成初始化的范围继续接收增量，不因初始缓存达到 5000 条而丢弃新消息**。按需模型证据更严格：候选 10 条、有限前后文、最多 20 页/1000 条记录、60 秒补取预算，正文预算 150 KB、总模型请求 256 KB；过量需缩小范围。

快照 ID、查询游标、变更游标分别保存。快照读完才用同范围的 boundary_cursor 接续；旧时间戳的新捕获记录仍按变更游标进入。每批消息、幂等持久任务与接收游标在同一 SQLite 事务中发布。索引另行处理，失败缺口之前的连续水位单独显示。重复交付不重复创建消息/任务。

重启后索引队列可继续；网络同步先暂停，点击“恢复已登记范围”才续接。游标/数据集/来源变化保留明确错误，不能自动从头导入。确认后对选定范围点击“重新初始化此范围”；缓存和人工状态保留。停用旧范围后可登记新范围，停用不删除缓存。

Mac V1 **只提供 insert、首次捕获 record_revision=1**。QQ 上游修订、微信后补资料、撤回/删除、附件字节下载均未传播。Windows 在隔离样例验证了更新/删除失效处理，不能据此宣称真实来源已支持。最早/最晚时间不代表中间历史完整。

## 数据与模型边界

聊天使用独立私有 `chat/cache.sqlite3`（schema 1），不修改录音 Core 的 schema 或 Phone/Watch 协议。records/scopes 为来源缓存；search_index/tasks/answers 为可重建派生状态；user_account_links 为独立人工状态。索引重建、来源重新初始化及模型缓存失效不删除人工账号映射。当前 UI 以明确平台账号筛选，没有新增跨平台自动人物合并。

回答只有用户点击时才生成；不运行主动事项、主题、人物推断或每日总结。沿用现有 Codex ModelExecutionRunner，单项默认 180 秒、最多两次显式尝试，执行批次上限 100 次或 30 分钟；不会自动重试/启动新批次。超时、取消、预算耗尽分别显示。已存在的搜索不等待模型任务。

聊天正文、XML、文件名、引用和问题均作为不可信数据传给模型；模型不能调用 SQL、命令、文件、网络工具或向他人发消息。每个事实项必须引用本轮证据 ID；逐字原话还验证原文包含该字符串。仅可移除“原话：”/“原文：”及外层展示引号，内部文字必须逐字存在于引用原文，源正文不改写；当前回答处理版本 chat-answer-v2。正文未知或媒体占位符不能用来推断附件内容。后续消息在预算内额外补取；范围不足时不得断言最终安排、完成或全部历史不存在。回答记录来源代数；消息变更或数据集替换使旧回答失效。

## 有限复验

运行 `python tools/check_chat_integration.py --state-dir state/v3` 先检查真实契约和 coverage。带 `--scope-file` 可验一个明确平台、采集账号、会话和时间的私有 JSON；默认最多两页，每页 25 条，不打印正文或凭据。输出在受控状态目录的 `chat/live-acceptance.json`；这类 smoke 本身不能证明 CHAT_QUERY_V1_READY。

仓库的 `tests/fixtures/chat_query_v1/questions.json` 是 20 道**虚构**固定题，真实验收材料只在 `state/chat-acceptance/`。不得把 fixture 导入 Mac 真源，或把人工预期写进聊天正文。

手机/手表仓库：NO CHANGE；本轮未实施指南后续第 20/21 节。

完整固定范围复验可运行 `python tools/retest_chat_fixed_scopes.py --scope-file state/chat-acceptance/fixed-scopes.json --state-dir state/v3 --output-dir state/chat-acceptance/retest-run`。范围文件是本机私有材料，需包含1–5个明确账号/会话/起止时间；超出页数/时间预算会停止并报告，不能据此声称范围已完整。
