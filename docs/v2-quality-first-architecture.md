# AllDayRecording-ASR V2：质量优先架构与实施设计

> 状态：已接受；V2-A/V2-B/V2-C 已于 2026-08-28 实现并进入真实长录音验收
> 决策日期：2026-08-28  
> 当前开发输入：`data/` 中已经入库的 2 小时 44 分 Watch M4A 录音  
> 未来输入：Watch 每 5 分钟关闭并上传一个原始音频块；自动上传和手动同步共用同一接收协议

## 1. 决策摘要

V2 不以实时性、低显存或最小模型为目标，而以真实 Watch 录音上的最终识别质量为第一优先级。系统采用多阶段、可重复、可比较的离线处理：使用当前可本地部署的高质量 ASR、强制对齐和说话人模型，允许同一音频保留多份模型假设，再将选定转写交给云端 LLM 完成语义整理。

以下约束不可被后续实现弱化：

1. Watch 上传或手工导入的原始音频永久保存、永不原地修改、永不被派生产物覆盖。
2. 当前开发不等待 Watch 同步功能，继续使用现有长录音完成 schema、模型、评测和工作台升级。
3. 当前长录音和未来 5 分钟音频块必须进入同一套核心处理管线，不能维护两套算法实现。
4. 不要求本地运行 LLM；本地 GPU 专用于音频识别、对齐、分离和声纹。摘要、事件和行动项之后通过可替换的云端接口实现。
5. 不要求实时 ASR。自动上传可行时后台传输，不可行时由用户点击同步；两种方式不得改变数据格式或处理结果。
6. 模型选择以冻结的真实 Watch 真值集为准。公开榜单用于选择候选模型，不能替代本项目评测。

## 2. 产品目标与非目标

### 2.1 V2 目标

- 最大限度提高中文、方言、中英混说、远场和噪声条件下的识别质量。
- 正确表达说话人切换和重叠讲话，不再强制一个 VAD 段只能属于一个人。
- 为字符或词保存可靠时间戳，并将文字按时间与说话人活动融合。
- 保留原始识别、候选识别、最终选择、人工修订和云端修订的完整历史。
- 任何文字、身份、事件或行动项都能追溯到原始音频对象和精确时间范围。
- 支持同一输入运行多个模型和配置，并进行不破坏旧结果的 A/B 评测。
- 当前长文件处理稳定后，可无缝接收按 5 分钟上传的音频块。

### 2.2 V2 非目标

- 不以低于一秒的字幕延迟为验收条件。
- 不在本地运行通用 LLM。
- 不在本阶段实现 Watch 上传客户端、云端供应商绑定或真实日历写入。
- 不以减少模型数量或缩短处理时间为优先目标。
- 不将匿名说话人聚类自动等同于真实人物身份。
- 不让云端 LLM 无痕覆盖声学模型的原始输出。

## 3. 原始音频不可变与永久保存

### 3.1 数据分级

| 数据级别 | 示例 | 保留策略 | 是否允许修改 |
| --- | --- | --- | --- |
| 原始证据 | Watch M4A、未来 5 分钟原始块 | 永久保存；必须可做完整性审计 | 否 |
| 人工事实 | 连续时间真值、身份确认、行动项审核 | 永久保存并保留修订历史 | 只允许新增修订 |
| 模型结果 | ASR 假设、词时间戳、speaker turns、分数 | 按 run 版本保存；允许重新生成 | 不覆盖旧 run |
| 可重建缓存 | PCM、降噪音频、试听 WAV、mel 特征 | 空间不足时可删除 | 是 |
| 展示产物 | Markdown、JSON、网页缓存 | 可重建 | 是 |

### 3.2 原始证据不变量

每个原始音频对象必须保存：

- 内容 SHA-256。
- 原始文件名、字节数、容器和编码元数据。
- 设备、录制开始时间、时区和持续时间。
- 首次发现时间和导入方式：`manual_file`、`watch_auto` 或 `watch_manual_sync`。
- 当前存储路径、备份状态、最后一次完整性校验时间和结果。
- 如果属于分块录音，还需保存 `day_id`、`chunk_index` 和设备声明的时间范围。

应用只能以只读方式打开原始对象。标准化、响度调整、降噪、重采样和裁剪必须写到独立的派生目录。任何命令都不得将临时文件移动或替换到原始路径。

“永久保存”不能只依赖同一磁盘上的一个文件。V2 schema 需要记录备份与校验状态；真正的第二存储介质或备份位置由后续单独设计和授权，本阶段不自动复制私人音频到任何外部位置。

### 3.3 当前长文件与未来音频块

当前 2 小时 44 分录音登记为一个原始对象和一个录音会话。管线在读取时创建逻辑处理窗口，不修改或物理切割原件。

未来每个 5 分钟 M4A 是独立原始对象，同一天的有序音频块组成一个录音会话。算法层面对两种输入统一暴露为虚拟时间轴：

```text
当前：一个长 M4A ───────────────┐
                                 ├─ 虚拟连续时间轴 ─ 模型处理窗口
未来：chunk 0 + chunk 1 + ... ──┘
```

## 4. 目标处理架构

```text
不可变原始音频对象
  ↓ 完整性校验、时间轴装配、边界连续性检查
逻辑处理窗口（默认 5–15 分钟，可带边界上下文）
  ↓
声学分析层
  ├─ speech / non-speech
  ├─ speaker change / overlap
  └─ music / media / noise / uncertain
  ↓
多 ASR 假设层
  ├─ Qwen3-ASR-1.7B 主假设
  └─ Fun-ASR-Nano-2512 对照假设
  ↓
Qwen3-ForcedAligner-0.6B 字符/词级对齐
  ↓
Sortformer / pyannote 说话人活动时间轴
  ↓
词时间戳 × 说话人时间轴融合
  ↓
本人声纹验证与其他人物匿名聚类
  ↓
最终转写选择、人工修订和质量标记
  ↓
可替换的云端语义接口
  ├─ 会话边界与主题
  ├─ 日记和事实
  └─ 日程/待办候选
  ↓
带原音证据的时间线、搜索、审核和导出
```

### 4.1 时间轴是核心，不再以 VAD 段作为唯一事实

V2 将以下时间轴分别保存：

- 原始对象在录音会话中的时间范围。
- 声学区域和重叠讲话区域。
- ASR 字符/词时间戳。
- 说话人活动区间，允许同一时刻有多个说话人。
- 身份匹配区间与分数。
- 会话、事件和行动项区间。

最终显示片段是这些时间轴融合后的视图，不是底层唯一存储单位。一个显示片段可以包含多名说话人；同一个说话人在一个片段中也可以多次进入和离开。

### 4.2 处理窗口与 5 分钟边界

- 当前长文件先按固定逻辑窗口读取，不生成长期保存的整段 PCM。
- 未来 5 分钟块到达后，先验证块序号、时间范围、哈希和相邻边界。
- 如果相邻块连续，可将前一块尾部、当前块和后一块头部组成带上下文的逻辑窗口。
- 边界处默认保留 3–5 秒分析上下文，最终只提交非重复的中心时间范围。
- 必须检测 M4A 编码器延迟、重复帧或时间空洞；不能假设文件拼接天然无缝。
- speaker ID 不能在每个 5 分钟块中永久重置。块内标签经过日级 embedding 关联后形成会话级匿名人物。

## 5. 模型与运行策略

### 5.1 固定候选

| 任务 | V2 首选 | 角色 |
| --- | --- | --- |
| 主 ASR | Qwen3-ASR-1.7B | 全量高质量识别 |
| 第二 ASR | Fun-ASR-Nano-2512 | 生成独立假设，发现分歧和专名问题 |
| 强制对齐 | Qwen3-ForcedAligner-0.6B | 字符/词级时间戳 |
| 说话人分离 | Sortformer、pyannote Community-1 | 在真实 Watch 真值上比较后确定默认路线 |
| 本人声纹 | 现有 CAM++ 为基线，加入至少一个独立模型候选 | 开放集本人验证，不直接继承聚类身份 |
| 声学事件 | SenseVoice 标签作为基线，必要时增加专用分类器 | 电视、音乐、噪声和不确定来源辅助判断 |

官方模型入口：

- [Qwen3-ASR](https://github.com/QwenLM/Qwen3-ASR)
- [FunASR](https://github.com/modelscope/FunASR)
- [NVIDIA NeMo speaker diarization](https://github.com/NVIDIA-NeMo/Speech/tree/main/examples/speaker_tasks/diarization)
- [pyannote.audio](https://github.com/pyannote/pyannote-audio)

这些名称是首批实施候选，不意味着公开榜单结果可以直接决定生产默认值。模型升级后必须保留当前 SenseVoiceSmall + FSMN-VAD + CAM++ 结果作为可复现基线。

### 5.2 质量优先推理

同一音频允许保留多份 ASR 假设。以下内容自动进入复核队列：

- 两个 ASR 在规范化后明显不一致。
- 人名、地名、数字、日期、时间、金额和否定词不一致。
- 对齐失败、重复生成、空转写或异常长输出。
- ASR 判定有语音但声学层置信不足，或声学层判定有语音但 ASR 为空。
- 重叠讲话、电视声、强噪声和跨块边界。

复核可以使用更长上下文重新运行主模型、使用另一条增强音频分支、交给人工，或在用户明确允许时调用支持音频的云端模型。纯文本 LLM 不能作为声学歧义的唯一裁决者。

### 5.3 GPU 资源

8 GB 环境继续支持开发和单模型验证；16 GB 环境作为完整 V2 推荐配置。模型按阶段顺序加载，通过独立 worker 进程释放显存，不要求 ASR、aligner、diarizer 和声纹模型同时常驻。

处理速度只作为运行指标记录，不作为牺牲准确率的理由。只有在两个配置质量等价时，才以速度、显存和磁盘占用决定默认值。

## 6. 音频缓存与存储

V2 不再长期保存整条录音的 `normalized-16k-mono.wav`。模型读取策略为：

1. 从不可变原始对象按逻辑窗口解码。
2. 将 16 kHz 单声道 PCM 写入有明确 run 和时间范围的临时缓存，或直接以内存/流方式传给模型。
3. 降噪、响度调整等处理必须建立独立分支，原始解码分支始终保留。
4. 缓存使用 LRU 或显式清理策略，删除缓存不得影响重新生成结果。
5. 试听 WAV 也是缓存；网页可以再次从原始对象按时间范围生成。

缓存键至少包含：原始 SHA-256、源时间范围、变换名称、变换参数哈希和实现版本。这样同一模型运行可以安全复用，参数变化不会误用旧缓存。

## 7. 数据模型目标（schema v4 起步）

schema v4 建立不可变 source/session、run 输入快照和派生产物基础；schema v5 增加冻结 truth、prediction snapshot 和 benchmark run；schema v6 增加不可变双 ASR 假设、alignment token、逐 token 原音映射和分歧队列；schema v7 增加重叠/exclusive speaker turns、逐 turn source trace 和 token speaker attribution。后续实体继续通过只追加的新 migration 引入。完整数据模型采用“不可变 run + 可选当前结果指针”，不得继续用覆盖单行的方式保存所有阶段结果。

### 7.1 核心实体

| 实体 | 用途 |
| --- | --- |
| `source_objects` | 不可变原始音频、哈希、元数据、完整性和备份状态 |
| `recording_sessions` | 一天或一次录音会话的逻辑时间轴 |
| `session_sources` | 原始对象在会话中的顺序和时间映射 |
| `processing_runs` | 模型、版本、配置、输入哈希、状态和父 run |
| `derived_artifacts` | 可重建文件及其内容哈希、类型和来源 run |
| `acoustic_regions` | speech、overlap、media、noise 等时间区域 |
| `asr_hypotheses` | 每个模型的文本假设、语言和质量信息 |
| `asr_alignment_tokens` | 字符/词文本及 analysis/session 开始、结束时间 |
| `asr_token_sources` | token 到不可变原音对象、SHA-256 和源时间的完整映射 |
| `asr_disagreements` | 同窗口两份 ASR 假设的差异与复核优先级 |
| `speaker_turns` | 说话人活动区间，允许重叠 |
| `speaker_attributions` | token/区间到匿名说话人和身份候选的关联 |
| `identity_scores` | 声纹模型、分数、校准版本和质量门槛 |
| `transcript_revisions` | 模型选择、人工修订和云端修订历史 |
| `truth_intervals` | 独立于模型切分的连续时间真值 |
| `semantic_candidates` | 事件、事实、日程和待办候选及证据 |

### 7.2 时间坐标

所有时间结果同时保留：

- `session_start_ms/session_end_ms`：相对录音会话的时间。
- `source_object_id` 与 `source_start_ms/source_end_ms`：对应原始文件内的范围。
- 可计算的绝对时间和时区。

任何展示结果必须可以反查到一个或多个原始对象范围。跨 5 分钟边界的句子允许引用两个源对象。

### 7.3 版本与复用

- run 的唯一身份由输入哈希、模型 checkpoint、运行时代码版本和 canonical config hash 共同决定。
- 修改模型、阈值、热词、增强方式或切分策略会产生新 run，不能复用不匹配的旧结果。
- 选定默认结果只更新指针，不删除其他假设。
- schema v3 数据必须通过新增 migration 升级；不得修改既有 migration。
- 现有 `speech_segments` 在迁移期作为 V1 兼容输出，不能继续作为 V2 真值和模型比较的唯一基础。

## 8. 云端 LLM 边界

本地音频管线先输出带时间戳、说话人和证据引用的结构化转写。云端接口之后接收：

- 选定转写及备选分歧。
- 会话上下文、日期和允许使用的个人词表。
- 每条输入对应的原始音频引用标识，但默认不包含音频字节。

云端输出必须符合 JSON schema，并保存供应商、模型版本、请求配置、响应哈希和证据映射。云端结果只能新增 `transcript_revision` 或 `semantic_candidate`，不能修改原始 ASR 行。

默认策略是不上传原始音频。以后若用户明确允许使用云端音频模型，只上传需要复核的最小音频范围，并单独记录授权和请求日志。云端供应商尚未决定，因此 V2 只能依赖内部接口，不能把某家 SDK 写进核心领域模型。

## 9. 评测与模型晋级规则

### 9.1 真值升级

当前基于 `segment_id` 的真值继续保留为历史基线，但不能作为 V2 唯一评测集。V2 真值必须锚定：

- 原始对象 SHA-256。
- 连续源时间范围和会话时间范围。
- speech/non-speech、说话人活动和重叠区域。
- 参考文字、人物身份、关键实体和事实。

这样更换 VAD、ASR 或 diarization 后仍能使用同一真值，并能统计系统完全漏掉的语音。

### 9.2 指标

| 层 | 必须报告的指标 |
| --- | --- |
| 声音活动 | Miss、False Alarm、边界偏差 |
| ASR | CER、精确匹配率、关键实体 Precision/Recall/F1 |
| 对齐 | token 起止时间误差、失败率 |
| 说话人 | DER、JER、重叠讲话子集 DER、speaker-attributed CER/cpCER |
| 本人身份 | Precision、Recall、FAR、FRR、EER、每小时误接受数 |
| 语义 | 事实召回、无证据事实率、日程/待办 Precision/Recall |
| 工程 | RTF、峰值 VRAM/RAM、缓存与原始数据磁盘占用、失败恢复率 |

报告必须按安静、远场、室外、电视、重叠、短句、中英混说和跨块边界分层。汇总指标不能掩盖关键场景退化。

### 9.3 晋级原则

- 当前 SenseVoice 基线不删除。
- 新 ASR 必须在冻结真值上显著降低 CER，并且关键实体不得退化，才能成为默认模型。
- 公开榜单更强但本地 Watch 音频更差的模型不得晋级。
- 如果两个模型各自在不同场景占优，保留按场景路由或双模型复核，不强制只留下一个模型。
- 评测集与声纹 accepted 样本继续保持会话隔离，禁止用测试答案更新模型档案。

## 10. 实施阶段

### V2-A：不可变数据与运行版本（已完成）

1. 新增 schema v4 migration 和上述核心 run/source 实体的最小集合。
2. 将当前长录音登记到 `source_objects` 和 `recording_sessions`，不移动原文件。
3. 增加完整性审计命令，验证 SHA-256、大小和媒体元数据。
4. 将缓存和原始证据分级，停止新增长期整段 PCM。
5. 建立长文件逻辑窗口读取器和未来 chunk 输入接口。

验收结果：schema v3 升级前自动备份；既有 V1 表逐表计数一致；现有 2 小时 44 分原始文件在迁移、完整性审计和真实窗口解码前后 SHA-256 不变。录音被规划为 33 个完整覆盖的 5 分钟核心窗口，真实 10 秒核心窗口可临时解码并在使用后删除。

### V2-B：连续时间真值与基准框架（已完成）

1. 新增与模型 segment 无关的真值格式。
2. 将现有 15 分钟标注映射到绝对时间；无法可靠映射的内容保留历史状态，不伪造真值。
3. 增加 VAD、DER/JER、对齐和关键实体指标。
4. 固化同一输入多 run 对比报告。

验收结果：schema v5 建立冻结真值、源范围引用、预测快照和 benchmark run；合成穷尽真值已验证 VAD Miss/FA、DER/JER、对齐误差和实体指标。现有 15 分钟标注映射为 277 条连续事实，冻结当前 V1 的 971 条预测后 CER 仍为 `0.1436`。旧标注源于 V1 VAD，系统明确将真实 VAD/DER 标为 N/A；完成穷尽式连续标注后即可统计真实漏检，不伪造结果。

### V2-C：高质量 ASR 与对齐（已完成）

1. 接入 Qwen3-ASR-1.7B backend。
2. 接入 Qwen3-ForcedAligner-0.6B。
3. 接入 Fun-ASR-Nano-2512 第二假设。
4. 保存多假设、token 时间戳和分歧队列。

## 11. 兼容和安全迁移
