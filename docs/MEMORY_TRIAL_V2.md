# 跨天记忆 V2：有限真实新消息试运行（ASR 0.7.4 / Phone 1.0.12）

复用 ChatQueries 的 Mac CHAT_DATA_CONTRACT_V1 主动拉取、ChatCache 的 records/tasks/scopes 和事务游标。没有新的采集服务、线程、定时扫描或同步队列。现有桌面进程须持续运行，Mac 捕获流程须向其数据服务投影提供新消息，设备接收端须可达；Windows 不控制 Mac 上游采集频率。Mac 当前只提供 insert/首次修订；真实更新和撤回未支持，Windows 修订失效逻辑只能合成验证。

`/people` 的跨天记忆入口增加三日试运行状态，`GET /api/v3/memory/trial` 只读状态、不分析。`POST` 显式 start/pause/resume/stop；start 选已有 1～3 联系人和同一来源账号、已缓存唯一单聊会话，不根据显示名匹配。日期为启动所在 Asia/Singapore 自然日至第三日，记录确切启动时刻，第三日结束自动关闭，首日只观察启动之后。联系人和时间范围不自动扩张。

启动记录快照 boundary、既有接收游标、最高已有 task ID、基线消息数和原记忆修订。启动前稳定 ID/修订已存在的消息属于基线，不按新的 Windows 入库时刻当实时消息。本轮临时范围不读取启动前快照历史，使用成功获得的 boundary 作为基线直接接续 changes；正常同步范围不被跳过。发生时间早于启动、但启动后首次沿 changes 到达的未缓存消息标为历史补录；只有发生时间在观察时段、此前不存在的稳定 ID、并沿基线边界后的 changes 游标成功提交才标为新消息。缺少 changes 游标证据的首次内容保守处理，不制造实时样本。来源修订单独计数；启动前已有内容被修订时仅按保存引用更新受影响证据状态，不重新分析基线历史。

消息、持久 tasks 和接收游标仍同一事务提交。tasks 的可空附加列保存本轮归属、类别、处理状态、来源游标对和接收/成功提交/处理完成时间，不新增并行队列，不重建原始库。旧 cache schema 1 原位兼容加列，既有 tasks/人工账号关系不变。提交后另记成功提交时间；若在两步之间中断，记录时间未知而非编造。稳定唯一键防重复。同一修订不同正文按原契约拒绝。

现有聊天线程每 30 秒只检查本轮最多三会话，持久轮替首个检查会话以免一个超时范围使其他会话饥饿；每会话至多两页、每页 100，整个检查有 15 秒软截止（进行中的请求仍受已有网络超时限制）。原始正常会话设置保留；试运行最多增加三个临时范围，临时初始化预算 5000，不挤占正常范围的初始预算。网络失败保持原游标和明确错误，原有有限重试不会在页数耗尽时静默吞掉错误。

成功提交和索引完成后在该线程合并触发：约两秒合并等待，最多每 30 秒一批。处理仅使用本轮有游标证明的 live/revision 收据，至多 5000 条、三日、三联系人；不重放启动前及补录历史。复用七段处理预算、已保存积压、失败回滚、新旧公平轮替、稳定讨论 ID 与人工决定。达到输入预算暂停并显示 TRIAL_RECORD_BUDGET_REACHED，保留积压。后台不根据新消息创建任务/Calendar 提醒或修改事项。无需人物页面或继续处理按钮触发。

相关性、安全附件投影及可信关联沿用 V1。被排除的促销仍保留本轮必要来源，后续本人询价可重新考虑；不会给联系人永久分类。无法证明同一事情只形成原机制的少量审核建议，确认、拒绝和撤销仍走既有审计和手机 outbox/回执/冲突。

跨库两阶段发布：Core 记忆事务先成功，再标记 cache 收据；中断后重用稳定 ID/batch_id 恢复，没有提前消费处理进度。暂停保持所有游标、积压及来源设置；恢复继续相同窗口；停止/到期恢复原有启用设置，只禁用本轮临时范围，不启动下一轮。试运行没有独立后台循环，仍由原线程负责，重启读取保存状态，到期先关闭触发。

状态显示新消息/补录/修订、处理/等待/排除/索引失败、失败次数及原因、讨论进度、最后检查/最新新消息/完成时间、原/最新记忆修订。最多 20 条本地收据显示消息发生、成功入库、记忆完成时间，及覆盖对应修订的现有手机确认时间（仅保留最新确认，不能代表首次抵达）；来源时钟超前则延迟未知并单列偏差，不把负数改成零。手机确认使用现有 sync_cursors 的 acknowledged_sequence/updated_at 与记忆 change sequence 比较，表示服务端收到的成功应用后游标确认；不是猜测响应抵达手机的时刻。离线没有确认时间。

手机保持原“人物 → 跨天互动 → 事情/原文”。现有前台 PhoneSyncCoordinator 在配对且接收端可达时自动拉取，空闲通常约 120 秒、有待发送等活动约 15 秒；退到后台不会新增持续唤醒。不需要手机分析聊天，也没有新的手机命令或资源类型。

契约兼容补丁 3.10.2、投影 7、Core 对外 34/私有 35、Phone 21 保持不变。Phone 1.0.12 只更新兼容契约收据和版本，记忆页面、同步代码不变。原始工作区修改、身份、声纹、录音、提醒和人工操作不得覆盖。原文/附件访问材料/配对信息/审核包仅留本地忽略输出。

合成回归模型 0 次：真实工作线程自动触发、事务提交/回滚、重复和迟到来源、断网、处理失败和重启、7+24 积压及新互动公平性、关联拒绝及修订/删除失效、暂停/恢复/停止/到期。Phone 原有实际 SQLite 回归覆盖离线 outbox、重放、回执及冲突。不向生产注入演示事实。
