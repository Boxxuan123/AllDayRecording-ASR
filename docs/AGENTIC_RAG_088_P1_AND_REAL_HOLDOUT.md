## P1 修复边界

独立报告的两条探针在 0.8.7 基线复现：用户根范围为 room-A，模型目标 room-B，缓存与远端都能接纳 B。

- InvestigationTools 单独深拷贝 root_scope，动态目标及结果 scope 的后续变化不能重写它。明确平台、人物、账号、会话与请求日期约束始终取交集；冲突不执行读取，并报告覆盖不足。
- 模型可见的目录对象受根范围过滤。即使后续注册了范围外引用，search 的执行前交集仍会阻止读取。
- 本地查询、远端请求、关联会话、上下文及最终证据接纳均执行根范围限制；关联会话 SQL 直接带账号/会话条件。指定会话下不能核实归属的全局记忆不读取。证据保存的上下文范围也保留硬筛选。
- 自动从问题匹配到的目录联系人只是调查起点，由解析层记录其来源；用户明确选择的联系人保持硬筛选。这个来源标记不增加人物识别规则，避免把正常的跨会话调查全部禁用。
- 自然目标日期仍可按原窗口查询受限后续；用户显式 sent_from/sent_to 为不可扩大的边界。原模型、时间、请求及数据量限额全部保持。

修复后原两条探针均隐藏 B 的目录引用并拒绝执行。另有新增回归直接注册 B，确认仍然没有本地/远端读取；同目标 A 的双方消息、关联缓存限制、上下文和直接证据、根范围深拷贝、硬平台/人物/日期，以及无会话硬筛选的合法跨会话均覆盖。

工程首次回归出现一个已有群查询正例失败：过滤模型目录后，账户授权回退也错误使用了被过滤目录。修复为授权目录与可见对象目录各自保留，远端仍须与根范围取交集；没有删除或修改原测试期望。最终门禁结果见本报告附后的验收记录及审核包 manifest。

## 真实盲测方法与预算

用户本轮明确授权最多三个虚构盲测。运行既有封存三题，SHA-256 `7ace614fbfeeec75ceb809d12b44f11b343ef4877c704bb6fb7f0f38238e7d1f`；未改题、标准答案未发给模型。模型运行前固定生产改动文件哈希，运行后复核一致。代码固定后才读取 evaluation_only 作人工评分。

通过现有 RecallInvestigatorAdapter / ModelExecutionRunner 调用真实 SDK，SDK 0.160.0，model=None（沿用默认模型），effort=low；回执没有提供最终解析的模型名称，未猜测型号。每个案例独立虚构数据库和空模型工作目录，禁止工具执行，全部来源为虚构夹具。

本轮仅为盲测运行器增加逐次输入、返回决策、错误、耗时记录，以及最多三题检查；没有增加生产调用权限。总上限 6 次 / 180 秒；实际尝试 **4 次**，返回 **2 次**，超时 **2 次**，总耗时 **90.5 秒**。未用剩余额度重试，也没有第四个案例。超时子进程均记录为通过独占 Windows Job 终止。

| 云杉译读会／同名不同事件 | 两轮真实调用耗时 19.469 与 18.093 秒；仅在原群搜索，未沿稳定账号找到私聊 6302；最终输出校验失败 | 取证不完整且协议失败，无有效最终回答 |

第三题的可复查失败：

1. get_message_context 的 targets 为空，只把消息 ID 放在 evidence_ids，实际没有展开上下文。
2. 后续搜索仍针对原群；没有调用 get_related_conversations 或选择已有私聊对象，遗漏次日限定说法。不是根范围门禁阻止了跨会话：该题自动群匹配为调查起点，其他目录对象仍在模型输入中，合法跨会话回归也通过。
3. 最终 claim 的 event_time.basis 为 unknown，却同时提供 evidence_id 和 quote。离线用相同校验器重放，确定抛出 `unknown time must remain unspecified`。应用按原规则拒绝结论，没有放松校验以使测试通过。
4. 原始返回文字没有直接指控违规，也没有合并同名不同账号；但没有发布有效答案，不能把这种有限观察计作整体身份/事实分级能力通过。

三个案例 **0 个有效最终回答**。其中两个没有可评分的模型决策，不能把超时解释成模型必然不会推理。25 秒包括 SDK 启动、通信及生成；当时全量回归并行运行，未分离服务端推理时延。
