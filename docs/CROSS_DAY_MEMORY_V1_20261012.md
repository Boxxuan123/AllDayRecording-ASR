## 使用路径

- 电脑：人物（`/people`）或总结与关系（`/insights`）→ 有依据的跨天互动与事情。首次使用展开日期与联系人选择，盘点缓存、选择最多三位联系人、选取并更新。无需输入内部 ID 或先生成每日总结。
- 人物 → 最近互动 → 具体事情／独立讨论 → 查看依据。聊天原文按已有 context 查询打开；录音复用片段播放与转写纠正入口。已有事项链接进入原跟进详情。
- 手机：人物 → 跨天互动与事情 → 最近互动与涉及的事情 → 具体事情／话题 → 查看原文依据。聊天仅同步必要原话与出处；完整聊天上下文在电脑查看。录音继续使用已有片段播放。
- 双端可选择另一条讨论，人工确认同一件事；有明确回复依据时进入现有人物审核，提供“关联到这件事／不是同一件事”。撤销一条记录的关联恢复独立，不修改原事件。
- 手机离线纠正进入原 outbox，等待原同步回执；同一索引有待处理操作时禁止再入队。来源变化造成 CAS 冲突须同步并重新判断，原人工记录可追溯。

## 复用与边界

复用稳定人物、来源账号命名空间、人工账号关联、ChatCache、已完成结构化录音事件及引用、Event 跟进、变化审核、correction_operations、change_events、设备操作队列和回执。新增的两张 Core 表是固定证据索引的不可变修订及可撤销关联决定；手机新增可重建索引投影。没有新增人物库、任务状态、提醒逻辑或后台调度。

私聊非本人发送者的实际互动可以进入人物卡，无需本人任务准入。群聊缓存不自动进入个人记忆。账号仅沿用现有可靠关联或人工确认；同名独立账号、相似内容和声纹候选不合并。未知录音说话人只作为录音讨论索引，不生成已知人物事实，也不改变任何声纹画像资格。

每段讨论保留时间、原文出处、修订、自述／转述／行为待核实类型，以及可获得的系统获知时间。原文中约定时间仍保留在原句，不从含混 ASR 补出日期或行为。已发送、已完成、取消等状态始终由现有跟进决定；准备婉拒不等于已回复。每日回顾不作新事实来源。

可信稳定 Event ID 可串联事情；具体原消息回复只产生待确认建议。相同话题按有限原文词语聚合，保留各次独立讨论；不代表个人观点或偏好。没有语义自动合并或模型调用。

单次入口限 1–3 个完整新加坡自然日，缓存读取上限 5000 条，最多 7 段讨论加 3 个话题，每段至多 8 条引用、每条至多 600 字。同范围与联系人重复更新复用固定清单，刷新只重验这些来源修订；新增日期或联系人需用户明确选择。没有全历史重跑。

来源删除、原文修订、发送者身份依据变化及录音纠正仅重验固定引用，标记旧证据失效；不继续显示为已确认。拒绝和撤销保留决定，重复分析、同步重放及重启不会复活关联；候选不会通过同一已确认事情的其他记录绕过拒绝。人工决定在原 correction_operations 中留痕。
