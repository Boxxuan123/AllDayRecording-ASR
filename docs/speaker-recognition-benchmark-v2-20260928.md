# Speaker Recognition Benchmark V2：离线实验报告

> 历史回顾性实验，使用 batch-padding 修复前的向量缓存，不属于独立验收。当前推理一致性修复、独立 reservation 和未来模型 benchmark 的门槛以 [Phase 4](speaker-verification-phase4-20261001.md) 为准。本轮归档没有重跑本实验或改变这些历史结果。

日期：2026-09-28。结论类别：**B，有改善信号，但真实自动轨验证仍不足。生产修改建议：暂缓。** 本轮只新增离线脚本、结果和报告；未修改生产识别逻辑、正式数据库、人工标注或自动确认策略。

## 1. 最重要的发现：旧测试真值被自动事实污染

先核查了旧实验的 `pilot.py`、冻结协议、`manifest.json`、`vectors.npz`、`frozen-settings.json` 和逐条预测。原报告的 555 个向量均存在，原音副本可访问，向量有限且范数在 0.99999994–1.00000012；按日期和会话划分，跨 split 原音 SHA 重复为 0，选中窗口之间没有重叠。旧代码在验证集选参数，未在测试集调阈值，但测试结果在本轮之前已经公开，因此 V2 仍属**回顾性分析**。

发现旧 `pilot.prepare()` 使用了所有 `active` 人物事实，没有区分人工事实与 `system:speaker-cluster-identity` 自动生成事实。555 个窗口中有 **29 个测试窗口仅靠系统事实给出人物标签**；建库和验证窗口均有完整人工人物事实。旧测试 `known 16/22` 是该污染数据集上的确切复算数字，但不能当作有效真值上的召回率。

V2 保留旧划分、原音和 CAM++ 缓存，只保留被有效、非系统人物事实完整覆盖且无相反人工标签的窗口，冻结为 [manifest.json](../outputs/speaker-recognition-benchmark-v2-20260928/manifest.json)。结果为 **526 个向量**：训练 191（含 10 个旧最长窗口）、验证 166、测试 169；可评分测试组变为已知 16、库外 21。移除清单见 `excluded-label-windows.json`，划分及来源核查见 `split-audit.json`。人工事实来自旧数据账本，未逐条重听；完整覆盖不等于纯净单人语音。

## 2. 受控窗口实验

主要单位为同一人工标签下最多五个时间分散窗口的平均查询向量，且总语音至少 6 秒。它**不是**自动 diarization 轨或连续 5–10 秒自然对话。下面所有新参数只在验证集选择；测试结果仅用于事后比较。表内“错人”指已入库人物被赋成另一个已入库人物。

| 方法 | 已知认对 | 已知召回 | 错人 | 库外误接收 | 已知拒识 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 固定建议阈值 0.92、margin 0.05 | 0/16 | 0% | 0 | 0/21 | 16 |
| 原会话均值原型 + 验证集阈值 0.42、margin 0.10 | **10/16** | **62.5%** | 0 | **0/21** | 6 |
| 同一原型 + 分人物阈值、margin 0.10 | 8/16 | 50.0% | 0 | 0/21 | 8 |
| 20 秒跨日期选样 + 单中心、阈值 0.48、margin 0.05 | 8/16 | 50.0% | 0 | 1/21 | 8 |
| AS-Norm + 验证集校准 | 6/16 | 37.5% | 0 | 3/21 | 10 |
| 逐窗口分数均值 + 验证集校准 | 9/16 | 56.3% | 0 | 1/21 | 7 |

生产匿名阈值 0.82 在同样输入下也是 0/16。这里的“原会话均值原型”沿用旧 pilot：每个训练会话的五个最长窗口先求一个中心，再对该人物的会话中心取最高匹配分；不是把该人物全部历史窗口求一个中心。生产当前匹配策略默认匿名阈值 0.82、人物建议阈值 0.92、margin 0.05；这些离线阈值**不能**直接写回生产。

校准基线在测试集的人物召回：母亲 6/7、张卫平 3/8、方庆声 1/1。库外 21 组包含父亲、庞乾静、本人各 7 组。测试观察到 0/21 次误接收的单侧 95% 二项分布上界仍约 **13.3%**；4 个测试会话的 session bootstrap 已知召回 95% 区间约 37.5%–100%，不能据 1–2 组差距宣称稳定改善。

分人物阈值的验证集支持数：母亲 14 正例、张卫平 7、方庆声 7；对应阈值 0.490、0.478、0.420。使用向全局 0.42 收缩的规则；样本少于 5 正例或 5 负例时回退全局值。它在受控测试集比全局校准少认对 2 组，不能称为整体优胜。

## 3. 真实自动轨代表窗口

重新扫描测试日期、原始自动轨的候选 voice prototype，排除标注后衍生 prototype，并只用**人工人物事实**评定代表窗口。37 条中：单一人物完整覆盖 24、多人物标签 1、不完整 2、无人工标签 10。24 条可评分 prototype 来自 4 个会话；它们只有 **11 个按原音重叠合并后的证据簇**，其中本人同一会话的 10 条高度相关，不能看成 24 个独立测试样本。建库与这些轨的原音 SHA 无交叉。只评代表窗口，没有证明整条自动轨都属一人，也没有串联独立本人 matcher。

| 验证集选定方案 | 已知认对 | 已知拒识 | 错人 | 库外拒识 | 库外误接收 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 校准原会话均值原型 | 4/7 | 3 | 0 | 14/17 | **3/17** |
| 分人物阈值 + margin | 4/7 | 3 | 0 | 17/17 | **0/17** |
| 20 秒跨日期单中心 | 4/7 | 3 | 0 | 17/17 | **0/17** |

基线的三次误接收全是“本人 → 张卫平”，同属 2026-09-27 一个原音重叠证据簇：最高分 0.453、0.435、0.434，margin 0.114、0.120、0.126，均略过 0.42/0.10。固定 margin 0.10 **挡不住**；由验证集推得的张卫平阈值 0.478 挡住了这三条，并未降低这 7 条已知轨的认对数。这是**可能改善**，不是显著优于全局阈值的独立证据：三条是一个失败事件，且受控窗口的已知召回反而减少。即使观察到 0/17，未知误接收率的单侧 95% 上界仍约 16.2%。当前真实轨证据 **insufficient for production acceptance**。

## 4. 各实验组回答

**A：校准与开放集。** 最大的可量化收益来自校准：固定 0.92 为 0/16，验证集选的全局阈值与 margin 为 10/16 且受控库外 0/21。只用最高分、margin 0 的测试结果是 6/16、库外误接收 1/21；固定 margin 0.05 为 6/16、0/21；联合验证集选择 0.42/0.10 为 10/16、0/21。AS-Norm 用训练窗口作 cohort 后是 6/16、误接收 3/21，在目前只有三位建库人物的规模下**不值得进入生产**。分人物阈值对本人错误有信号，但窗口召回损失，统计证据不足。

**A5：鲁棒聚合。** 五个片段分数的 mean、median、trimmed mean、top-2 mean 分别为 9/16+1 次库外误接收、5/16+1、5/16+0、6/16+0，均不优于查询向量求均值的 10/16+0。每组最多五个相关片段，2-component GMM 无可靠拟合基础，标记为 `insufficient evidence`，没有虚构 GMM 收益。

**B：建库规模与选样。** 对三位已知人物分别以 20/40/60/90 秒和全部训练窗口选样，随机策略 5 个固定 seed；整窗口选样会略超预算。只看单中心随机策略，测试已知认对平均依次约 7.0、6.2、6.2、4.8、7.0/16；20 秒时 seed 范围为 5–10/16。最长、跨日期、简化质量筛选也没有随秒数单调提高。这里存在明显场景和抽样波动，**无法指定可靠的 20/40/60/90 秒最优值**；不能据此支持无限堆历史标注。质量筛选只使用时长和训练向量一致性，没有可靠 SNR/overlap 标签，不能把它解释为真正干净语音筛选。

**B：表示方法。** 在同一选样上比较单中心、时长加权中心、逐维中位中心、2/3 中心与所有单窗口原型，共 40 组匹配的选样配置。每种表示在测试上的平均库外误接收次数依次约 0.28、0.30、0.57、1.25、1.40、2.02；“全部单窗口原型”还平均产生 0.23 次错人。原型取最大分会抬高库外最高分，例如同一 40 秒随机样本从单中心均值 0.537 升至全原型 0.579。此前 multi-prototype 失败有**最大值评分扩大误接收机会**的直接证据；不能只归咎于样本质量，当前也未找到风险约束下稳定胜过原会话均值的方法。

**C：质量规则。** 受控五窗口组的 `abstain` 与动态阈值仍是 10/16、0/21，简单分数降权为 8/16、0/21；组的质量大多足够高。单窗口诊断中，原规则 27/72 已知认对、4/97 库外误接收；低质量拒识为 17/72、2/97，降权及动态阈值各为 22/72、2/97。降低误接收伴随明显拒识，未证明净收益。质量分数基于时长和向量一致性，尚未测信噪比、削波、重叠与 VAD 纯度。

**D：时间聚合与延迟。** 单窗口单独校准为 23/72 已知认对、6/97 库外误接收；在最多五窗口的人为同人组上，累计 3/5/10/20 秒的方案分别为 11/16+2/21、10/16+1/21、10/16+2/21、10/16+1/21。分母和分组来源不同，不能把这些数直接当作“多等几秒减少多少真实轨错误”。用固定 0.42/0.10 从每组前缀第一次过门槛就永久提交，平均提交语音时长约 7.47 秒，最终 14/16 已知认对，但库外误接收 **4/21**；在本项目错误代价下是退步。真实自动轨的逐句时间决策数据不足，**不建议据此采用 delayed commitment**。

**E：持续学习。** 按日期滚动，先识别当天、再把当天人工标签加入后续 profile；阈值固定，不把未来数据提前建库。可评分的几个后期日里，“全部先前窗口”对 60 秒早期窗口截取的已知认对分别为 2026-09-13 的 6/7 对 3/7、09-22 的 7/14 对 4/14、09-27 的 3/9 对 2/9；但 09-22 全量方案有 1 次库外误接收，有限方案为 0。这种滚动实验混用了旧划分中后续可用的人工标签，且各日场景不同、只有少数日期，不足以证明更多标注持续改善，也不足以确定 profile 容量。它只能支持“需要验证受控增量更新”，不能直接上线持续学习。

## 5. 风险指标与失败案例

记录了已知识别准确率/召回、拒识率、库外误接收率、错人率、宏平均人物召回及逐人物误接收。项目风险代价定义为 `k × (错人 + 库外误接收) + 拒识`，分别保存 k=5、10、20。受控测试的校准基线代价均为 6；分人物阈值均为 8；20 秒跨日期方案为 13/18/28。真实轨代表窗口的三组代价依次为基线 18/33/63、分人物 3/3/3、20 秒跨日期 3/3/3，但后两种的优势来自同一个重叠的本人事件。不能以一个人为权重或相关 prototype 数量批准生产修改。

所有被测方案的受控错认和库外误接收、三种轨方案的错误，以及入选方案的拒识案例、分数、次高候选、margin、时长、质量、日期、会话和原音范围在 `failure-cases.json`。典型拒识：一些张卫平受控组分数低于门槛或 margin 不足；本人自动轨出现**高分且错人**，不能用简单“只拒绝低质量”解释。原音边界是可追溯指针，未重听全部疑难原音，仍需人工复核其纯净度与真实身份。

## 6. 对十二个问题的决定

| 问题 | 当前证据结论 |
| --- | --- |
| Q1 最大瓶颈 | 校准和拒识边界有明确影响；短窗口、跨条件 profile 波动、自动轨相关性也明显。无法把剩余错误单独归因于 CAM++ embedding 或 diarization 污染。 |
| Q2 明显优于校准均值？ | **没有稳定证据。** 分人物阈值降低一个本人错误事件，但牺牲 2 个受控已知组。 |
| Q3 AS-Norm？ | 不建议进入生产；本数据上 6/16、库外误接收 3/21。 |
| Q4 分人物校准？ | 可能改善本人误接收，尚未显著优于全局校准。 |
| Q5 hard negative / margin？ | 固定 0.10 margin 未挡住本人→张卫平；验证集分人物阈值挡住，仍需新独立录音验证。 |
| Q6 GMM / robust？ | 已测简单聚合无收益；GMM 样本不足。 |
| Q7 cluster 聚合？ | 人工同人组比短片段更稳的信号存在；真实自动 cluster 增益未证实。 |
| Q8 delayed commitment？ | 当前 first-pass 模拟约 7.47 秒，库外误接收升至 4/21，不值得直接采用。 |
| Q9 enrollment 秒数？ | 无稳定最优；20–90 秒结果不单调，跨日样本量不足。 |
| Q10 更多标注？ | 不能证明持续提高，也不能证明有限精选总优；需要新的逐日独立验收。 |
| Q11 多原型为何差？ | max 评分抬高库外分数及误接收；当前未发现可信胜出条件。 |
| Q12 现在改生产？ | **B / 暂缓**：回顾性测试真值曾污染，真实轨仅 4 会话、11 重叠证据簇，且本人错误集中同一事件。 |

## 7. 可复现性与下一步

在仓库根目录运行：

```powershell
.\.venv\Scripts\python.exe tools\benchmark_speaker_recognition_v2.py --output outputs\speaker-recognition-benchmark-v2-replay-new
```

重放必须指定 `outputs/` 下不存在的新目录；旧实验目录及其冻结设置、预测不会被覆盖。脚本本身未重新提取模型向量，当前重放仍只能解释历史缓存和当下人工事实的回顾性结果。

脚本以 SQLite `mode=ro` 和 `query_only` 读取正式库，重新核对人工事实并生成所有结果。使用 Python 3.12.10、NumPy 2.5.2、FunASR 1.4.4、Torch 2.9.1+cu128；生产同款 `FunASR/CAM++ v1-local` 权重 SHA-256 为 `3388cf5fd3493c9ac9c69851d8e7a8badcfb4f3dc631020c4961371646d5ada8`。完整 manifest 哈希、固定种子、数据库 revision 19746 和 Git commit 见 `verification.json`。输出目录：`outputs/speaker-recognition-benchmark-v2-20260928/`，包含协议、审计、冻结 manifest/设置、各组 JSON、逐人 CSV、汇总 CSV、失败案例和验证记录。原音与输出目录本地私有，受 `.gitignore` 忽略。

下一步仅三项：

1. 人工复听本人误认事件及自动轨未覆盖的 13 条代表窗口，核对混人、噪声与标签边界；记录独立原音事件而非重复 prototype 数。
2. 预留新的不同日期、设备和环境的陌生人及熟人录音，先冻结真值与验收指标，再盲测全局和分人物阈值。
3. 在真实 diarization 轨上采集逐片段时间线，比较保留 Unknown、累计证据和分人物阈值的错人事件与识别延迟；通过后再设计生产改动。
