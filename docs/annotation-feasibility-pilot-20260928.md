# 标注数据是否足够：离线可行性实验

> 历史报告。后续 [Benchmark V2](speaker-recognition-benchmark-v2-20260928.md) 发现 29 个旧测试窗口仅有系统人物事实；下文原始 16/22 结果不能作为有效人工真值上的召回率。V2 排除后为 10/16，仍不足以批准生产修改。[Phase 4](speaker-verification-phase4-20261001.md) 又确认并修复 batch-padding 推理不一致；本报告保留当时结果，不代表当前独立验收。

日期：2026-09-28。决策：**现有数据足够筛选改进方向，尚不足以批准自动识别上线；本轮不支持立即重构成多片段声纹匹配。原始自动轨的补充检查出现误认，生产实施继续暂缓，优先进一步验证校准和数据一致性的小到中等改动。**

## 1. 实际做了什么

没有修改生产代码、正式数据库、人工标注、自动确认开关或服务。单独建立本地实验目录，以只读事务获取有效标注，用已有本地 CAM++ 模型重新提取了 555 个原音窗口的向量，全部成功。

先保存实验协议，再提取声音和计算分数。按日期隔离数据：

| 数据用途 | 日期数 | 录音会话数 | 时间分散抽样窗口数 |
| --- | ---: | ---: | ---: |
| 建库 | 4 | 5 | 181 |
| 选择阈值、候选差距和方法 | 3 | 4 | 166 |
| 留出测试 | 3 | 4 | 198 |

以上共 545 个窗口；另有 10 个建库窗口用于精确重现当前最长五段选样，共提取 555 个窗口。不是 555 次独立对话。检查了跨集合的原音文件摘要重复和录音时间交叉，未发现泄漏；抽样窗口在各人物会话内不重叠。

已知人物库包含母亲、张卫平、方庆声。本人作为熟人库的干扰身份，不测试或修改独立本人 matcher。父亲和庞乾静不进入建库和调参，专门检验测试时会不会误认未入库人物；其他少量人物和本人提供验证负例。

阈值及候选差距只用验证集确定。验证目标要求声音组中没有误认，然后最大化各人物平均召回。方法也只按验证集选择，参数保存在 `frozen-settings.json` 后才评估测试集。

## 2. 比较结果

主要评价单位为“按现有人工人物标签，把时间顺序上相邻的五个抽样片段合成一个声音组”。它模拟多片段说话轨的声纹输入，使用相同的平均查询向量，保留当前合计六秒的质量门槛。最后不足五段也计入；不满六秒仍在分母中，记为未知。

**这使用了人工人物边界，不能当作自动说话人切分后的端到端准确率。** 抽样片段可能相距较远，声音组也不等于自然连续语音。

留出测试共 43 组：22 组已入库人物、21 组未入库人物。

| 方法 | 熟人认对 | 熟人认错为其他熟人 | 未入库人物被误认 |
| --- | ---: | ---: | ---: |
| 当前最长五段平均声纹 + 固定 0.92、差距 0.05 | 0 / 22 | 0 | 0 / 21 |
| 同一平均声纹 + 验证集校准 | **16 / 22（72.7%）** | **0** | **0 / 21** |
| 同样五段分别保留、取最高相似度 + 校准 | 10 / 22（45.5%） | 0 | 2 / 21 |
| 时间分散选五段、分别匹配 + 校准 | 11 / 22（50.0%） | 1 | 1 / 21 |
| 从最多 32 段中按中心性与差异选五段、分别匹配 + 校准 | 12 / 22（54.5%） | 0 | 1 / 21 |

固定 0.82 的平均声纹对照同样为 0 / 22。这是本次隔离建库后、固定测试声音组的结果，不代表生产库所有历史音频的实际识别率。生产熟人自动确认本来关闭，本表单独比较评分规则。

验证集预先选中的方法正是平均声纹，并非看过测试结果后更换赢家。校准后的平均声纹在验证组认对 24 / 28；测试各人物为：

- 母亲：6 / 7。
- 张卫平：9 / 14。
- 方庆声：1 / 1，只有一个声音组，证据很弱。
- 父亲、庞乾静、本人：各 7 / 7 组被拒绝为库外人物。

实验选出的全局阈值为 0.42，第一与第二候选差距为 0.10。**它仅是这三个身份、小规模验证集、特定输入聚合方式的实验参数，不是建议写回正式库的上线参数。** 数据、人物数量和输入方式改变都需要重新验证。

## 3. 为什么还不能上线

单独片段诊断去掉六秒总时长门槛，直接检验短片段声音可分性，同样使用已冻结参数：

- 校准平均声纹认对 50 / 101 个熟人片段（49.5%）。
- 97 个未入库人物片段中有 4 个被误认（4.1%）：父亲 2 个、本人 2 个。

这是与声音组不同的输入条件，不是正式系统的单句错误率；它明确说明不能把组级改善外推到所有短句，也不能将新阈值直接应用到所有现有入口。

### 原始自动轨补充检查：发现误认，未通过直接实施条件

主实验后又检查了留出录音中 15 条原始自动轨代表声纹，排除了标注后生成的样本集。沿用上面已冻结的平均声纹和阈值，重新从原始取样窗口提取向量，没有重新调参。

其中只有 7 条代表声音的窗口被现有有效人物事实完整覆盖，可按现有标注评分：

- 3 条库内人物：母亲、张卫平各认对 1 条；另 1 条张卫平被留未知。
- 4 条库外声音：父亲 1 条、庞乾静 2 条正确拒绝；**本人 1 条被错误认成张卫平**，最高分约 0.453，候选差距约 0.114。
- 另 8 条真值覆盖不完整，不能计为正确或错误；其中多条已有非空人物预测，需要核对原音才能判断。

这一补充检查仍只测试熟人匹配，未串联独立本人 matcher，也未证明代表窗口能够代表整条自动轨。它说明人工分组得到的 0 / 21 误接收，不能推出实际自动轨安全。不能直接采纳实验阈值并上线。下一阶段应优先补齐这 8 条的真值，再扩展真实轨及本人识别前后级联的验证。

其他限制：

1. 留出集只有 4 段录音、3 个日期，声音组和片段互相关联；0 / 21 并不能证明真实误认率接近零。
2. 测试阶段完全没参与调参的库外人物只有父亲、庞乾静两人，不能代表广泛陌生人或电视声音。
3. 真值沿用用户已有标注；没有对全部原音独立重听，也未验证所有粗粒度片段里是否只有一个人。
4. 使用人工身份分组，尚未测自动切分混人、漏分、同轨混合带来的损失。
5. 前一轮诊断看过部分历史聚合声纹分数。因此这是回顾性可行性筛选，不是完全盲测的最终验收；后续如果依据这些测试结果继续修改，必须留新的对话做最终测试。
6. 此次只检验三种具体多片段方案，不能据此断言所有多原型算法都无效，也未验证完整的质量筛选与场景建模设计。

## 4. 数据量到底够不够

| 人物/目标 | 当前证据 | 能支持的判断 |
| --- | --- | --- |
| 母亲 | 6 段录音，4 个日期 | 能做跨日期方法筛选 |
| 张卫平 | 5 段录音，4 个日期 | 能做跨日期方法筛选 |
| 方庆声 | 3 段录音，3 个日期，测试日只有约 24 秒标注 | 能初筛，测试量明显不足 |
| 父亲 | 2 段人物事实录音，2 个日期 | 不足以分成独立建库/调参/测试三组，本轮用作库外测试 |
| 庞乾静 | 258 条标注集中在 1 段录音 | 可以检查同场景声音，不能证明跨天身份识别 |
| 李伟杰、黄鑫、陈泰杰 | 各自仅一段录音的少量片段 | 不足以单独验证人物识别 |
| 低误认率和完整自动流程 | 缺更多独立人物、场景和真实自动说话轨评估 | 当前不足 |

因此，不需要先补成千上万条标注再启动实验。真正缺的是独立日期、人物、录音条件和经核对的测试边界，而非总标注条数。

## 5. 对修改计划的调整

前一份诊断提出了局部重构声纹学习模块的候选方案。本次实验后应收缩实施范围：

### 现在有证据支持

- 修同原音重复、相反审核冲突和有效样本统计不一致。
- 保留现有平均声纹作为基线，完善阈值选择与验证过程，报告具体失败原因。
- 给校准/重匹配增加可追踪的版本和失败恢复，避免已保存审核与后续处理脱节。

### 暂不批准

- 全面改为逐片段最高分匹配或多个代表片段匹配。本轮三个候选均未优于校准平均声纹。
- 将本次 0.42 阈值写回生产库或自动开启人物确认。
- 宣称系统已经达到 72.7% 的端到端识别率。

### 开工前下一道验证

1. 扩展本次原始自动轨检查，先补齐 8 条未完整覆盖的代表声音真值；人工标注只用于评分。明确混合人物轨的判断方式，并测试独立本人识别与熟人匹配级联。这一步可先利用已有原音和历史处理结果，不重构生产系统。
2. 对本轮错误与疑难样本做定向回听，先核对标签与切分边界，不把误标直接解释成模型能力不足。
3. 方庆声增加独立测试录音；父亲、庞乾静各补不同日期对话，覆盖建库、调参、最终留出三种用途。优先不同距离、房间和设备，避免重复同一场景。
4. 预先留出新的未入库人物及电视/远场/混音场景。阈值只在验证集选择，最终测试不反复用于调参。
5. 按人物报告召回、错认、留未知及审核量；至少不能用降低拒识带来的误认增加换取“看起来更准”。

最终建议：**先做校准和数据一致性的最小改进验证，暂缓声纹表示重构。** 本轮证明了验证先行的价值：实际数据已经帮我们排除了三个当前不值得直接实施的方向。

## 6. 可复现文件

实验目录：`outputs/annotation-feasibility-20260928/`。

- `PROTOCOL.md`：提取和评分前保存的协议。
- `pilot.py`：prepare / embed / evaluate 三步本地脚本。

- `verification.json`：向量完整性、指标复算和参数一致性检查。
- `automatic-track-label-coverage.json`：原始自动轨代表窗口的人物事实覆盖。
- `track_probe.py` / `automatic-track-probe.json`：冻结参数的原始自动轨补充实验与逐条结果。
